# [DeepSeek Harness插件内核-03]利用Fiber管理Context和插件的生命周期

在 Cordis 中，管理插件与上下文生命周期的核心引擎并不是传统应用中的全局注册表，而是一个名为 Fiber 的状态机与执行单元。作为 Context 和 Plugin 生命周期的真正管理者。每一个被加载的插件实例，在 Cordis 运行时中都会被包裹在一个独立的 Fiber 作用域内。Fiber 充当了状态机的角色，负责监控插件的依赖是否满足，并精确追踪该插件在 Context 上创建的所有待释放资源，以便在卸载时执行资源清理和释放工作。

## 1. Fiber的公共属性

Fiber具有两种典型的创建方式，一是在创建根Context的时候，会创建一个Fiber对象作为当前上下文生命周期管理器，对应Context的fiber属性。另一种就是在调用RegistryService的plugin方法注册插件的时候，会创建对应的fiber对象作为插件专属的生命周期管理器。前者用于释放整个上下文的资源，后者用于释放绑定的插件以及资源。我们下来看看Fiber提供了哪些属性成员：

```typescript
export class Fiber {
  public uid: number | null
  public readonly ctx: Context
  public config: any
  public _config: any
  public state = FiberState.PENDING
  public readonly dispose: () => Promise<void>
  public store: Dict<Impl> | undefined
  public inertia: Promise<void> | undefined
  public readonly _hooks: Dict<DisposableList<Function>> = Object.create(null)
  public readonly _disposables = new DisposableList<Disposable>()
}
```

定义在Fiber类中的各个公共属性成员说明如下：

- **uid**：Fiber 实例的唯一自增 ID。用于日志追踪、调试排查、以及可视化拓扑图中标识该执行单元。通过 `uid`，框架可以精确知道当前是哪一个插件实例在控制台输出日志或抛出了异常；
- **ctx**：当前 Fiber 所绑定的专属子上下文（Context）实例。在 Cordis 中，插件看到的 ctx 实际上是它专属的子 Context。这个 `ctx` 内部持有了指向当前 Fiber 的引用；
- **config**：插件当前生效的配置。当用用户修改了当前绑定插件的配置时，加载器会将全新的配置对象赋给此属性，它是插件运行时直接读取的动态业务参数；
- **\_config**：插件在上一次处于激活状态时的历史配置快照。主要用于高频的热重载（Hot Reload）机制。通过与最新的 `config` 进行深度差异比对，框架能决定是直接应用新配置还是安全地重启插件；
- **state**：当前的生命周期状态机指针。调度引擎会频繁读取并修改这个状态，用来控制该插件是否应该对外部暴露服务，或者是否应该拦截其向外发送的事件；
- **dispose**：触发该 Fiber 彻底销毁的异步显式函数句柄。当外部调用此方法时，Fiber 会切入**卸载状态**，逆向清空所有注册的资源、解绑事件、释放内存，并将自身从主 Context 树中连根拔起；
- **store**：当前插件自己向外声明并提供的服务实现映射表。如果该插件实现了某个 Service，此属性会存储该服务的具体类实例。当外部依赖该服务的其他下游插件加载时，框架会从这里提取实现并注入到下游；
- **inertia**：异步生命周期迁移的**守护锁** Promise。在动态热重载或高频切换配置的场景下，用于防止同一个插件同时触发**正在启动**和**正在销毁**，有效避免生命周期状态产生时序竞争导致的死锁；
- **\_hooks**：插件私有的、局部生命周期钩子（Hooks）注册表。当插件通过自己的 ctx.on() 注册事件监听时，callback 会分类记录在这里的 `DisposableList` 列表中，实现空间隔离，让 Fiber 对插件自身产生的生命周期钩子拥有绝对控制权；
- **\_disposables**：一个用于存放待释放资源的DisposableList对象。每当插件创建了任何释放资源，返回的可销毁句柄都会推入此列表。当 Fiber 执行销毁时，会按注册的相反顺序自动、彻底地将这些资源全部释放。

## 2. Fiber状态机

Fiber 通过一套严密的内部状态机，管理着插件从“出生”到“消亡”的完整一生。 具体的状态定义在如下所示的`FiberState`枚举中：

```typescript
export const enum FiberState {
  PENDING,
  LOADING,
  ACTIVE,
  FAILED,
  DISPOSED,
  UNLOADING,
}
```

具体状态说明如下：

- **PENDING (挂起等待)**：插件已被实例化，但其通过 `inject` 声明的服务依赖尚未完全就绪。此时插件处于**睡眠**排队状态，不对外产生任何影响；
- **LOADING (正在加载)**：所有强依赖的服务均已上线。Fiber 开始初始化插件，执行插件内部的 `apply(ctx)` 函数。此时正在建立局部钩子（`_hooks`）并收集由插件产生的待释放资源；
- **ACTIVE (正常运行)**：`apply` 函数顺利执行完毕，无异常抛出。插件正式进入激活状态，其自身向外提供的服务（存储于 `store` 中）对外界可见，注册的事件、命令与定时器正式生效；
- **FAILED (启动失败)**：在 `LOADING` 阶段，若插件的 `apply` 函数在执行过程中抛出未捕获的异常，状态机将捕获该错误并存入 `error` 属性，同时将状态标记为 `FAILED`，防止崩溃污染全局；
- **UNLOADING (正在卸载)**：由于用户修改了配置文件、触发了热重载，或者上游依赖的服务突然下线，Fiber 接收到销毁信号。此时 `_disposables` 队列开始按后进先出（LIFO）的顺序，逆向执行清理待释放资源；
- **DISPOSED (完全销毁)**：所有绑定的局部钩子、定时器、网络连接等待释放资源已被完全释放，`uid` 被置为 `null`。该 Fiber 实例已变成纯粹的空壳，等待垃圾回收机制（GC）将其从内存中彻底释放。

它通过响应式依赖追踪和可逆资源释放机制，控制插件从加载、激活到销毁的完整过程：

```text
       [ 载入插件 ]
            │
            ▼
     ┌──────────────┐
  ┌─►│   PENDING    │◀────────────────┐ (依赖的服务被卸载)
  │  └──────────────┘                 │
  │         │                         │
  │         │ (所有声明的依赖均就绪)    │
  │         ▼                         │
  │  ┌──────────────┐                 │
  │  │   LOADING    │                 │
  │  └──────────────┘                 │
  │         │                         │
  │         ├─── (apply 执行抛出异常)  │
  │         │     │                   │
  │         │     ▼                   │
  │         │   ┌──────────────┐      │
  │         │   │    FAILED    │      │
  │         │   └──────────────┘      │
  │         │                         │
  │         ▼ (apply 顺利执行完毕)     │
  │  ┌──────────────┐                 │
  │  │    ACTIVE    │─────────────────┤
  │  └──────────────┘                 │
  │         │                         │
  │         │ (配置更改/显式触发销毁)   │
  │         ▼                         │
  │  ┌──────────────┐                 │
  │  │  UNLOADING   │─────────────────┘
  │  └──────────────┘
  │         │
  │         ▼ (所有Disposables清理完毕)
  │  ┌──────────────┐
  └──│   DISPOSED   │
     └──────────────┘
```
