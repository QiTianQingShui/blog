# [Deep Agents:LangChain的Agent Harness-12]利用create_deep_agent整合所有的Harness中间件

Deep Agents调用调用`create_deep_agent`函数来创建一个Agent。我们在最开始已经说过，这个函数仅仅是在`create_agent`函数的基础上注册了一系列预定义的`Middleware`罢了。到目前为止，我们已经介绍了此函数涉及的绝大部分`Middleware`类型（除了针对Anthropic模型的`AnthropicPromptCachingMiddleware`）。下面给出了`create_deep_agent`函数的声明：

## 1. create_deep_agent参数列表

```python
def create_deep_agent(
    model: str | BaseChatModel | None = None,
    tools: Sequence[BaseTool | Callable | dict[str, Any]] | None = None,
    *,
    system_prompt: str | SystemMessage | None = None,
    middleware: Sequence[AgentMiddleware] = (),
    subagents: Sequence[SubAgent | CompiledSubAgent | AsyncSubAgent] | None = None,
    skills: list[str] | None = None,
    memory: list[str] | None = None,
    response_format: ResponseFormat | None = None,
    context_schema: type[Any] | None = None,
    checkpointer: Checkpointer | None = None,
    store: BaseStore | None = None,
    backend: BackendProtocol | BackendFactory | None = None,
    interrupt_on: dict[str, bool | InterruptOnConfig] | None = None,
    debug: bool = False,
    name: str | None = None,
    cache: BaseCache | None = None,
) -> CompiledStateGraph
```

所有参数说明如下：

- model: 用于Agent的语言模型，可以是一个字符串（如模型名称）或者一个`BaseChatModel`实例。如果没有显式指定，默认模型名称为`claude-sonnet-4-6`；
- tools: Agent可以使用的工具列表，每个工具可以是一个`BaseTool`实例、一个可调用对象或者一个工具定义的字典；
- system_prompt: Agent的系统提示词，可以是一个字符串或者一个`SystemMessage`实例； 
- middleware: Agent中要使用的`Middleware`列表，这些`Middleware`会在Agent的调用过程中被依次应用；
- subagents: Sub-Agent的定义列表，每个Sub-Agent可以是一个`SubAgent`对象、一个`CompiledSubAgent`对象或者一个`AsyncSubAgent`对象。它们用于创建注册的`SubAgentMiddleware`和`AsyncSubAgentMiddleware`，这两个中间件分别“[SubAgentMiddleware如何驱动Sub-Agent的协同演化](https://blog.csdn.net/JaydenAI/article/details/160966457)”和“[AsyncSubAgentMiddleware如何让Agent像微服务一样远程协作？](https://blog.csdn.net/JaydenAI/article/details/160967155)”中有详细说明；
- skills: 提供Skills的目录列表，方法会注册`SkillsMiddleware`中间件，“[通过SkillsMiddleware将Skill引入LangChain](https://blog.csdn.net/JaydenAI/article/details/160910652)”对它进行了详细介绍；
- memory: 提供Memory的目录或者文件路径列表，方法会注册`MemoryMiddleware`中间件，“[利用MemoryMiddleware构建能够自我学习和进化的Agent](https://blog.csdn.net/JaydenAI/article/details/160943421)”对它进行了详细介绍；
- response_format: 输出Schema类型，是实现格式化输出的关键；
- context_schema: 用于指定静态上下文Schema类型；
- checkpointer: 用于持久化的`BaseCheckpointSaver`对象，也可以指定为`None`或者`True`/`False`；
- store: 作为长期存储的`BaseStore`对象；
- backend: 后端存储或者创建后端存储的工厂，默认使用`StateBackend`；“[构建抽象的文件系统](https://blog.csdn.net/JaydenAI/article/details/160847515)”中后端存储进行了详细介绍；
- interrupt_on: 指定哪些工具调用会触发中断，以及中断的配置，用于创建注册的`HumanInTheLoopMiddleware`。“[通过HumanInTheLoopMiddleware引入人机交互](https://blog.csdn.net/JaydenAI/article/details/160911229)”对此中间件进行了详细介绍；
- debug: 是否启用调试模式，默认为`False`；
- name: Agent的名称，默认命名为`LangGraph`；
- cache: 用于结果缓存的`BaseCache`对象；

`subagents`参数提供的`SubAgent`和`CompiledSubAgent`用于创建注册的`SubAgentMiddleware`，而提供的`AsyncSubAgent`用于创建注册的`AsyncSubAgentMiddleware`。如果指定的`SubAgent`没有指定模型和工具集，那么它会继承`Main-Agent`的模型和工具集；否则使用自己独立的模型和工具集。除此之外，`SubAgent`还会默认合并如下四个`Middleware`：

- TodoListMiddleware：赋予Agent显式的规划和任务跟踪能力，“[TodoListMiddleware的任务拆解与状态流转](https://blog.csdn.net/JaydenAI/article/details/160876899)”对此中间件进行了详细介绍；
- FilesystemMiddleware：构建了一个抽象的文件系统，提供操作此文件系统的一系列工具集，“[FilesystemMiddleware：赋能Agent读写文件及管理长上下文](https://blog.csdn.net/JaydenAI/article/details/160876223)”对此中间件进行了详细介绍；
- _DeepAgentsSummarizationMiddleware：对话历史进行摘要的中间件，“[利用SummarizationMiddleware对长程对话瘦身](https://blog.csdn.net/JaydenAI/article/details/160942433)”对此中间件进行了详细介绍；
- PatchToolCallsMiddleware： 用于修正对话历史的消息结构，“[利用PatchToolCallsMiddleware修复错乱的消息结构](https://blog.csdn.net/JaydenAI/article/details/160942369)”对此中间件进行了详细介绍；

## 2. 系统提示词

`create_deep_agent`对于创建的Agent会默认添加上限为`1000`的迭代次数的限制。如果没有指定系统提示词，会默认使用如下的提示词。即使你指定了系统提示词，最终使用的提示词也会附加这么一段。

```markdown
You are a Deep Agent, an AI assistant that helps users accomplish tasks using tools. You respond with text and tool calls. The user can see your responses and tool outputs in real time.

## Core Behavior

- Be concise and direct. Don't over-explain unless asked.
- NEVER add unnecessary preamble (\"Sure!\", \"Great question!\", \"I'll now...\").
- Don't say \"I'll now do X\" — just do it.
- If the request is ambiguous, ask questions before acting.
- If asked how to approach something, explain first, then act.

## Professional Objectivity

- Prioritize accuracy over validating the user's beliefs
- Disagree respectfully when the user is incorrect
- Avoid unnecessary superlatives, praise, or emotional validation

## Doing Tasks

When the user asks you to do something:

1. **Understand first** — read relevant files, check existing patterns. Quick but thorough — gather enough evidence to start, then iterate.
2. **Act** — implement the solution. Work quickly but accurately.
3. **Verify** — check your work against what was asked, not against your own output. Your first attempt is rarely correct — iterate.

Keep working until the task is fully complete. Don't stop partway and explain what you would do — just do it. Only yield back to the user when the task is done or you're genuinely blocked.

**When things go wrong:**
- If something fails repeatedly, stop and analyze *why* — don't keep retrying the same approach.
- If you're blocked, tell the user what's wrong and ask for guidance.

## Progress Updates

For longer tasks, provide brief progress updates at reasonable intervals — a concise sentence recapping what you've done and what's next.
```

## 3. 利用DeepAgents重写我们的差旅助手

我们在这个系列的前两篇文章“[SubAgentMiddleware如何驱动Sub-Agent的协同演化](https://blog.csdn.net/JaydenAI/article/details/160966457)”和“[AsyncSubAgentMiddleware如何让Agent像微服务一样远程协作？](https://blog.csdn.net/JaydenAI/article/details/160967155)”中分别使用了`SubAgentMiddleware`和`AsyncSubAgentMiddleware`来实现了一个差旅助手。现在我们可以利用`create_deep_agent`函数来重写这个差旅助手，我们依然采用Sub-Agent的模式来实现。

### 3.1 部署住宿安排的Agent

我们采用AsyncSubAgent来远程访问单独部署的用于安排住宿的Agent，如下所示的是项目的目录结构：

```
project/
├── .env
├── langgraph.json
├── agent.py
└── pyproject.toml
```

Agent对应的Graph定义在agent.py中，具体代码如下所示：

```python
from langchain.agents import create_agent
from langchain.tools import tool
from langchain_openai import ChatOpenAI

@tool
def book_hotel(city: str, hotel: str, check_in_date: str, check_out_date: str):
    """酒店预订工具，提供城市、酒店、入住日期和退房日期，返回预订信息"""
    return f"Hotel booked in {city} at {hotel} from {check_in_date} to {check_out_date}"

graph = create_agent(
    model=ChatOpenAI(model="gpt-5.2-chat"),
    tools=[book_hotel],
    system_prompt=("你是一个专注于住宿安排的个人助理，可以帮助用户调用`book_hotel`工具预订酒店。"
                    "达成预订酒店的目标是首要任务，你可以自行决定酒店、房型和价格等级。"
                    "将预订信息以清晰的格式返回给用户。"))
```

如下所示的是定义在langgraph.json中配置：

```json
{
  "dependencies": ["."],
  "graphs": {
    "accommodation_agent": "./agent.py:graph"
  },
  "env": ".env"
}
```

### 3.2 利用create_deep_agent函数创建Agent

在如下的演示程序中，我们调用create_deep_agent函数创建了这个所谓的**深度**Agent。我们将创建的ChatOpenAI对象作为其model，注册的工具check_calendar用于查询用户的日程安排。subagents参数提供了两个Sub-Agent，一个是我们前面部署的住宿安排accommodation_agent，另一个是一个专注于出行安排的transport_agent，它们类型分别是AsyncSubAgent和SubAgent。我们在系统提示词中明确授权Agent可以调用这两个Sub-Agent来完成差旅安排的任务。

```python
from datetime import datetime, date
from typing import TypedDict
from langgraph.checkpoint.memory import MemorySaver
from langchain_core.runnables import RunnableConfig
from langchain.tools import tool
from deepagents import create_deep_agent, SubAgent, AsyncSubAgent
from langchain_openai import ChatOpenAI
from dotenv import load_dotenv

load_dotenv()

class Event(TypedDict):
    """日程事件"""

    title: str
    """事件标题"""
    description: str
    """事件描述"""
    start_time: datetime
    """事件开始时间"""
    end_time: datetime
    """事件结束时间"""


@tool
def check_calendar(date: date) -> list[Event]:
    """日程查询工具，提供日期，返回该日期的日程信息"""
    if date == datetime.now().date():
        return [
            Event(
                title="团队会议",
                description="与团队成员讨论项目进展",
                start_time=datetime.strptime(f"{date} 10:00", "%Y-%m-%d %H:%M"),
                end_time=datetime.strptime(f"{date} 11:00", "%Y-%m-%d %H:%M"),
            ),
            Event(
                title="客户电话会议",
                description="与客户讨论需求和反馈",
                start_time=datetime.strptime(f"{date} 14:00", "%Y-%m-%d %H:%M"),
                end_time=datetime.strptime(f"{date} 19:00", "%Y-%m-%d %H:%M"),
            ),
        ]
    return []

@tool
def buy_air_ticket(origin: str, destination: str, departure_date: str, flight_no: str):
    """机票购买工具，提供出发地、目的地、出发日期和航班号，返回购买信息"""
    return f"Flight ticket bought from {origin} to {destination} on {departure_date} with flight number {flight_no}"

transport_agent: SubAgent = {
   "name": "transport_agent",
   "description":"一个专注于出行安排的个人助理，负责处理与机票购买相关的安排。",
   "system_prompt": ("你是一个专注于出行安排的个人助理，可以帮助用户调用`buy_air_ticket`工具购买机票。"
                     "达成购买机票的目标是首要任务，你可以自行决定航司、航班和舱位等级。"
                     "将购买信息以清晰的格式返回给用户。") ,
   "model":ChatOpenAI(model="gpt-5.2-chat")
}

accommodation_agent:AsyncSubAgent = {
    "name":"accommodation_agent",
    "description": "一个专注于出行安排的个人助理，负责处理与机票购买相关的安排。",
    "url":"http://localhost:2024/",
    "graph_id":"accommodation_agent"
}

agent = create_deep_agent(
    model=ChatOpenAI(model="gpt-5.2-chat"),
    tools=[check_calendar],
    system_prompt=(
        "你是一个差旅助理，可以帮助用户安排差旅计划."
        "你可以调用`check_calendar`工具查询用户的日程安排，以便更好地规划差旅计划。"
        "如果没有日程安排冲突，你可以直接帮我购买机票和预订酒店。"
        "达成机票购买和酒店预订是首要目标，完全授予你自行选择航司、舱位、航班和酒店的权利，无需用户确认。"
    ),
    subagents = [transport_agent,accommodation_agent],
    checkpointer=MemorySaver(),
)
```

### 3.3 Agent测试

我们调用创建的Agent来测试一下它的能力。我们提供了一个差旅安排的请求，Agent会首先调用check_calendar工具来检查用户的日程安排，发现用户在后天有一个客户电话会议的日程安排，于是它会合理地规划差旅计划：购买明天出发、后天返回的机票，并预订明天入住、后天退房的酒店。

```python
config: RunnableConfig = {"configurable": {"thread_id": "thread_123"}}
result = agent.invoke(
    input={
        "messages": [
            {
                "role": "user",
                "content": "明后两天有一个从上海到北京的差旅计划，请帮购买往返机票（明天出发，后天返回）和预订酒店（入住明天，退房后天）。",
            }
        ]
    },
    config=config,
)
print(result["messages"][-1].content)
```
