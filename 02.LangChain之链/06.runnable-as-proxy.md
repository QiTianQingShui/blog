# [LangChain之链-06]使用Runnable实现配置绑定、失败重试、降级以及数据成员过滤

接下来介绍三个以**代理形式**存在的`Runnable`类型，其中`RunnableBinding`使`Runnable`对象可以绑定配置和参数，`RunnableRetry`则实现了针对失败重试策略的绑定。`RunnableWithFallbacks`可以在被代理`Runnable`对象执行失败后，利用一组`Runnable`对象作为后备。`RunnablePick`虽然不属于代理，但是使用起来类似于代理，因为它从被`代理`的`Runnable`的输出中摘取指定的成员。

## 1. RunnableBinding

为了避免在每次在调用`Runnable`对象的时候重复指定相同的配置和参数，我们可以这些配置和参数直接绑定在`Runnable`对象上。比如在如下这个演示实例中，我们自定义了一个`RunnableFoobar`类型，并在重写的`invoke`方法中传入的`RunnableConfig`和关键字参数打印出来。我们随后创建了一个`RunnableBinding`对象，并利用构造函数的参数提供了绑定的`RunnableFoobar`对象、`RunnableConfig`配置和关键字参数。

```python
from langchain_core.runnables import Runnable, RunnableBinding, RunnableConfig
from typing import Any

class RunnableFoobar(Runnable[Any, Any]):
   def invoke(
        self,
        input: Any,
        config: RunnableConfig | None = None,
        **kwargs: Any,
    ) -> Any:
        print(f"""\
config: {config}
kwargs: {kwargs}
            """)
        return input

runnable = RunnableBinding(
    bound= RunnableFoobar (),
    config={"configurable": {"baz": "ccc"}},
    kwargs={
        "foo":"aaa",
        "bar":"bbb"
    }
)

runnable.invoke(input={},config ={"configurable":{"qux":"ddd"}},quux ="eee")
```

我们调用最终`RunnableBinding`对象的`invoke`方法，并同时指定了配置和关键字参数。从如下的输出结果可以看出，绑定的配置和参数与调用时指定的配置和参数合并后的结果就是最终使用的配置和参数。

```
config: {'tags': [], 'metadata': {'baz': 'ccc', 'qux': 'ddd'}, 'configurable': {'baz': 'ccc', 'qux': 'ddd'}}
kwargs: {'foo': 'aaa', 'bar': 'bbb', 'quux': 'eee'}
```

`Runnable`的`bind`和`with_config`方法都会创建一个`RunnableBinding`对象。`RunnableBindingBase`是`RunnableBinding`的基类，在调用构造函数创建`RunnableBinding`对象的时候，我们不仅可以利用`bound`、`kwargs`和`config`参数绑定的`Runnable`对象、关键字参数和配置，还可以利用`config_factories`指定一组创建`RunnableConfig`配置的工厂，甚至可以利用`custom_input_type`和`custom_output_type`指定绑定的输入输出类型。与这些绑定内容相关的属性和方法在`RunnableBindingBase`中都会进行相应的改写。

```python
class RunnableBinding(RunnableBindingBase[Input, Output])

class RunnableBindingBase(RunnableSerializable[Input, Output]):
    bound: Runnable[Input, Output]
    kwargs: Mapping[str, Any] = Field(default_factory=dict)
    config: RunnableConfig = Field(default_factory=RunnableConfig)
    config_factories: list[Callable[[RunnableConfig], RunnableConfig]] = Field(
        default_factory=list
    )
    custom_input_type: Any | None = None
    custom_output_type: Any | None = None
    def __init__(
        self,
        *,
        bound: Runnable[Input, Output],
        kwargs: Mapping[str, Any] | None = None,
        config: RunnableConfig | None = None,
        config_factories: list[Callable[[RunnableConfig], RunnableConfig]]
        | None = None,
        custom_input_type: type[Input] | BaseModel | None = None,
        custom_output_type: type[Output] | BaseModel | None = None,
        **other_kwargs: Any,
    ) -> None:
        super().__init__(
            bound=bound,
            kwargs=kwargs or {},
            config=config or {},
            config_factories=config_factories or [],
            custom_input_type=custom_input_type,
            custom_output_type=custom_output_type,
            **other_kwargs,
        )

    @override
    def invoke(
        self,
        input: Input,
        config: RunnableConfig | None = None,
        **kwargs: Any | None,
    ) -> Output:
        return self.bound.invoke(
            input,
            self._merge_configs(config),
            **{**self.kwargs, **kwargs},
        )

   def _merge_configs(self, *configs: RunnableConfig | None) -> RunnableConfig:
        config = merge_configs(self.config, *configs)
        return merge_configs(config, *(f(config) for f in self.config_factories))
```

重写的`invoke`方法会直接调用绑定`Runnable`对象的`invoke`方法，当前调用提供的配置和关键字参数会与绑定的配置和参数进行合并后作为其参数。在合并配置的时候，不仅会使用绑定的配置，还用使用由配置工厂创建的配置。其他的`ainvoke`、`stream/astream`和`transform/atransform`方法也做了类似的重写。

```python
class Runnable(ABC, Generic[Input, Output]):
     def bind(self, **kwargs: Any) -> Runnable[Input, Output]:
        return RunnableBinding(bound=self, kwargs=kwargs, config={})

    def with_config(
        self,
        config: RunnableConfig | None = None,
        # Sadly Unpack is not well-supported by mypy so this will have to be untyped
        **kwargs: Any,
    ) -> Runnable[Input, Output]:
        return RunnableBinding(
            bound=self,
            config=cast(
                "RunnableConfig",
                {**(config or {}), **kwargs},
            ),
            kwargs={},
        )
    def with_types(
        self,
        *,
        input_type: type[Input] | None = None,
        output_type: type[Output] | None = None,
    ) -> Runnable[Input, Output]:
        return RunnableBinding(
            bound=self,
            custom_input_type=input_type,
            custom_output_type=output_type,
            kwargs={},
        )
    def with_listeners(
        self,
        *,
        on_start: Callable[[Run], None]
        | Callable[[Run, RunnableConfig], None]
        | None = None,
        on_end: Callable[[Run], None]
        | Callable[[Run, RunnableConfig], None]
        | None = None,
        on_error: Callable[[Run], None]
        | Callable[[Run, RunnableConfig], None]
        | None = None,
    ) -> Runnable[Input, Output]:
        return RunnableBinding(
            bound=self,
            config_factories=[
                lambda config: {
                    "callbacks": [
                        RootListenersTracer(
                            config=config,
                            on_start=on_start,
                            on_end=on_end,
                            on_error=on_error,
                        )
                    ],
                }
            ],
        )

    def with_alisteners(
        self,
        *,
        on_start: AsyncListener | None = None,
        on_end: AsyncListener | None = None,
        on_error: AsyncListener | None = None,
    ) -> Runnable[Input, Output]:
        return RunnableBinding(
            bound=self,
            config_factories=[
                lambda config: {
                    "callbacks": [
                        AsyncRootListenersTracer(
                            config=config,
                            on_start=on_start,
                            on_end=on_end,
                            on_error=on_error,
                        )
                    ],
                }
            ],
        )  
```

`Runnable`的`bind`、`with_config`、`with_types`、`with_listeners`和`with_alisteners`方法以如上的方式创建`RunnableBinding`对象，所以上面的例子可以简写成如下的形式。

```python
runnable = (RunnableFoo()
    .bind(
        foo = "aaa",
        bar = "bbb")
    .with_config(config={"configurable": {"baz": "ccc"}}))

runnable.invoke(input={},config ={"configurable":{"qux":"ddd"}},quux ="eee")
```

## 2.RunnableRetry

为 `Runnable` 添加自动重试策略的`RunnableRetry`是提升应用可靠性的关键组件。它专门用于处理因网络波动、模型限流或临时服务器错误而导致的瞬时失败。`RunnableRetry`是一个包装器，它包裹一个现有的`Runnable`。当被包裹的组件抛出指定的异常时，它会根据预设的策略自动重新尝试执行，而无需在业务逻辑中手动编写`try-except`或`while`循环。

比如在如下这个演示程序中，我们利用函数`create_runnable`创建了一个`RunnableLambda`对象，处理函数利用一个闭包使它会在前两次调用中抛出异常。我们以此`RunnableLambda`创建两个`RunnableRetry`，并将重试次数（包含最初的调用）分别设置为2和3，执行的结果表明前者会失败，后者会成功。

```python
from langchain_core.runnables import Runnable, RunnableLambda
from langchain_core.runnables.retry import RunnableRetry
from  typing import Any

def create_runnable()-> Runnable[Any, str]:
    counter = 0
    def handle(_:Any) -> str:
        nonlocal counter
        counter += 1
        if counter < 3:
            raise Exception(f"manually thrown exception")
        return "SUCCESS"
    return RunnableLambda(handle)

runnable = RunnableRetry(
    bound=create_runnable(), 
    max_attempt_number =2)

try:
    runnable.invoke(None)
    assert False, "Expected an exception to be raised"
except Exception as e:
    assert str(e) == "manually thrown exception"

runnable = RunnableRetry(
    bound=create_runnable(),
    max_attempt_number =3)
result = runnable.invoke(None)
assert result == "SUCCESS"
```

`RunnableRetry`和`RunnableBinding`一样同属`RunnableBindingBase`的子类。从它的构造含函数可以看出，它在现有可绑定元素基础上添加了针对重试策略的绑定，具体包括异常类型、最大重新次数以及与基于指数的退避重试（通过`ExponentialJitterParams`类型表示）和防抖开关。在重写的`invoke/ainvoke`、`stream/astream`和`transform/atransform`方法中，这些绑定的重试策略会被合并到指定的`RunnableConfig`中被应用。

```python
class RunnableRetry(RunnableBindingBase[Input, Output]):
    retry_exception_types: tuple[type[BaseException], ...] = (Exception,)
    wait_exponential_jitter: bool = True
    exponential_jitter_params: ExponentialJitterParams | None = None
    max_attempt_number: int = 3

    def __init__(
        self,
        *,
        name: str | None = None,
        bound: Runnable[Input@Runnable, Output@Runnable],
        kwargs: Mapping[str, Any] = dict,
        config: RunnableConfig = RunnableConfig,
        config_factories: list[(RunnableConfig) -> RunnableConfig] = list,
        custom_input_type: Any | None = None,
        custom_output_type: Any | None = None,
        retry_exception_types: tuple[type[BaseException], ...] = (Exception, ),
        wait_exponential_jitter: bool = True,
        exponential_jitter_params: ExponentialJitterParams | None = None,
        max_attempt_number: int = 3
    ) -> None

class ExponentialJitterParams(TypedDict, total=False):
    initial: float
    max: float
    exp_base: float
    jitter: float

class Runnable(ABC, Generic[Input, Output]):
    def with_retry(
        self,
        *,
        retry_if_exception_type: tuple[type[BaseException], ...] = (Exception,),
        wait_exponential_jitter: bool = True,
        exponential_jitter_params: ExponentialJitterParams | None = None,
        stop_after_attempt: int = 3,
    ) -> Runnable[Input, Output]:
        return RunnableRetry(
            bound=self,
            kwargs={},
            config={},
            retry_exception_types=retry_if_exception_type,
            wait_exponential_jitter=wait_exponential_jitter,
            max_attempt_number=stop_after_attempt,
            exponential_jitter_params=exponential_jitter_params,
        )	
```

`Runnable`定义的`with_retry`方法以如上的形式创建了`RunnableRetry`，所以上面的演示程序可以简写成如下的形式。顺便说一下，表示重试次数的参数以`stop_after_attempt`命名，但是构造函数对应的参数名是`max_attempt_number`。

```python
try:
    create_runnable().with_retry(stop_after_attempt=2).invoke(None)
    assert False, "Expected an exception to be raised"
except Exception as e:
    assert str(e) == "manually thrown exception"

runnable = create_runnable().with_retry(stop_after_attempt=3)
result = runnable.invoke(None)
assert result == "SUCCESS"
```

## 3. RunnableWithFallbacks

`RunnableWithFallbacks`同样是另一个`Runnable`对象的代理，针对它的调用会被它转发给被代理的对象。但是它会捕获调用异常，并根据设置的**降级策略**按照顺序调用预先提供的**后备Runnable**直至成功。比如在如下这个演示程序中，我们创建了三个`RunnableLambda`，并人为命名为`foo`、`bar`和`baz`。`RunnableWithFallbacks`是对`foo`的代理，`bar`和`baz`按序作为后备。被代理和第一个后备对应的`Runnable`（`foo`和`bar`）总是会抛出异常，但第二个后备`baz`会成功。所以针对`RunnableWithFallbacks`的调用最终会成功，而通过log列表的记录表明三个`Runnable`均参与进来。

```python
from langchain_core.runnables import RunnableLambda
from langchain_core.runnables.fallbacks import RunnableWithFallbacks
from  typing import Any
from functools import partial

log= []

def handle(name:str, throw_exception:bool,_:Any)-> str:
    log.append(name)
    if throw_exception:
        raise Exception(f"manually thrown exception in {name}")
    return "SUCCESS"

runnable = RunnableWithFallbacks(
    runnable=RunnableLambda(partial(handle, "foo", True)),
    fallbacks=[
        RunnableLambda(partial(handle, "bar", True)),
        RunnableLambda(partial(handle, "baz", False)),
    ])
    
result = runnable.invoke(None)
assert result == "SUCCESS"
assert log== ["foo", "bar", "baz"]
```

`RunnableWithFallbacks`派生于`RunnableSerializable`，它的`runnable`和`fallbacks`字段分别表示被代理的`Runnable`和后备`Runnable`列表。它还有两个额外的字段，其中`exceptions_to_handle`表示实施**降级策略**的异常类型。如果链以字典作为输入和输出数据，被代理或者前一个`Runnable`抛出的异常会写入作为输出的字典，以此传递给后面执行的`Runnable`。这个存储存储异常的Key通过`exception_key`进行设置。后备策略的实施实现在重写的`invoke/ainvoke`、`stream/astream`和`transform/atransform`方法中。

```python
class RunnableWithFallbacks(RunnableSerializable[Input, Output]):
    runnable: Runnable[Input, Output]
    fallbacks: Sequence[Runnable[Input, Output]]
    exceptions_to_handle: tuple[type[BaseException], ...] = (Exception,)
    exception_key: str | None = None
```

我们对前面略加改动来演示异常在处理流程中的传递。我们首先将三个`RunnableLambda`的输入、输出以及`log`变量均改写成字典，并在没有抛出异常的情况下在其中添加状态`（"status": "SUCCESS"）`表示成功执行。我们在创建`RunnableWithFallbacks`时将`exception_key`设置为“error”。每个`Runnable`在执行的时候，我们会利用这个Key从输入字典中提取前面抛出的异常，并添加到log中。程序给出的断言表明：`bar`和`baz`在执行的时候均能从输入字典中得到上一个`Runnable`抛出的异常。

```python
from langchain_core.runnables import RunnableLambda
from langchain_core.runnables.fallbacks import RunnableWithFallbacks
from functools import partial

log: dict[str, Exception|None] = {}

def handle(name:str, throw_exception:bool,input:dict)-> dict:
    log[name] = input.get("error", None)
    if throw_exception:
        raise Exception(f"manually thrown exception in {name}")
    return {**input, "status": "SUCCESS"}

runnable = RunnableWithFallbacks(
    runnable=RunnableLambda(partial(handle, "foo", True)),
    fallbacks=[
        RunnableLambda(partial(handle, "bar", True)),
        RunnableLambda(partial(handle, "baz", False)),
    ],
    exception_key="error")
    
result = runnable.invoke({})
assert result["status"] == "SUCCESS"
assert list(log.keys()) == ["foo", "bar", "baz"]
assert log["foo"] is None
assert str(log["bar"]) == "manually thrown exception in foo"
assert str(log["baz"]) == "manually thrown exception in bar"
```

`Runnable`定义的`with_fallbacks`方法会以如下的方式创建`RunnableWithFallbacks`对象。

```python
class Runnable(ABC, Generic[Input, Output]):
    def with_fallbacks(
        self,
        fallbacks: Sequence[Runnable[Input, Output]],
        *,
        exceptions_to_handle: tuple[type[BaseException], ...] = (Exception,),
        exception_key: str | None = None,
    ) -> RunnableWithFallbacksT[Input, Output]:
        return RunnableWithFallbacks(
            runnable=self,
            fallbacks=fallbacks,
            exceptions_to_handle=exceptions_to_handle,
            exception_key=exception_key,
        )
```
所以上面的例子针对RunnableWithFallbacks的创建可以改写成如下的形式。

```python
runnable =RunnableLambda(partial(handle, "foo", True)).with_fallbacks(  
    fallbacks=[
        RunnableLambda(partial(handle, "bar", True)),
        RunnableLambda(partial(handle, "baz", False)),
    ],
    exception_key="error")    
```

## 4.RunnablePick

`RunnablePick`是一个用于字段提取的`Runnable`类型。如果说`RunnableAssign`的作用是**加法**，那么`RunnablePick`的作用就是**减法**。`RunnablePick`的主要任务是从上游传来的字典中，根据指定的Key，提取出对应的值并将其作为下一步的输入。指定的Key对应`keys`字段，如果只提取单个成员，它可以是一个字符串，否则就是一个列表。具体的提取逻辑实现在`_pick`方法中，它对输入的验证表明`RunnablePick`只支持类型为字典的输入。`RunnablePick`重写的`invoke/ainvoke`、`stream/astream`和`transform/atransform`方法会调用此方法生成所需输出。

```python
class RunnablePick(RunnableSerializable[dict[str, Any], Any]):
    keys: str | list[str]
    def __init__(self, keys: str | list[str], **kwargs: Any) -> None:
        super().__init__(keys=keys, **kwargs)

    def _pick(self, value: dict[str, Any]) -> Any:
        if not isinstance(value, dict):
            msg = "The input to RunnablePassthrough.assign() must be a dict."
            raise ValueError(msg)  # noqa: TRY004

        if isinstance(self.keys, str):
            return value.get(self.keys)
        picked = {k: value.get(k) for k in self.keys if k in value}
        if picked:
            return AddableDict(picked)
        return None	
```

从定义可以看出，`RunnablePick`是一个独立处理字典数据的`Runnable`对象，并不是一个代理。但是我们一般不会直接创建它，而是调用某个`Runnable`对象如下所示的`pick`方法。这个方法会创建一个`RunnablePick`对象，并返回它与当前`Runnable`对象构建的管道。

```python
class Runnable(ABC, Generic[Input, Output]):
    def pick(self, keys: str | list[str]) -> RunnableSerializable[Any, Any]:
        return self | RunnablePick(keys)
```

`RunnablePick`虽然简单，但也隐藏一些容易忽略的细节：

- 如果针对单个成员的提取，并以字符串指定数据成员，会返回数据成员的值；否则返回的是字典；
- 如果指定成员部分不存在，不会有异常抛出，但是不存在的成员不会包含在返回的字典中；
- 如果指定的成员全部不存在，返回的是None，而不是一个空字典。

上面的这些规则体现在如下所示的演示程序中： 

```python
from langchain_core.runnables import RunnablePassthrough
runnable = RunnablePassthrough().pick(["foo", "bar"])
input = {"foo": "123", "bar": "456", "baz": "789"}
result = runnable.invoke(input)
assert result == {"foo": "123", "bar": "456"}

runnable = RunnablePassthrough().pick("foo")
result = runnable.invoke(input)
assert result == "123"

runnable = RunnablePassthrough().pick(["foo"])
result = runnable.invoke(input)
assert result == {"foo": "123"}

runnable = RunnablePassthrough().pick(["foo","qux"])
result = runnable.invoke(input)
assert result == {"foo": "123"}

runnable = RunnablePassthrough().pick(["qux","quux"])
result = runnable.invoke(input)
assert result == None
```
