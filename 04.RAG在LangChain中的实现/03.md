# [RAG在LangChain中的实现-03]利用向量存储实现基于自然语言的相似度检索

被分割的文本切片需要转换成向量保存在`VertorStore`中，才能实现基于自然语言的相似度检索。`VectorStore`是RAG架构的核心组件。它的主要作用是存储和检索非结构化数据的**语义特征**。简单来说，它就像一个具备**模糊匹配**能力的智能仓库。说到向量化，就不得不提一个名为**嵌入**的概念。

## 1. 嵌入（Embedding）

之前看到一个问题：“是什么成就了大语言模型？”，我想很多人的答案是深度神经网络。如果答案只有一个的话，我觉得**嵌入**居功至伟，如果没有嵌入将数据转换成可处理的向量，一切都是空谈。虽然现代的LLM都是通过深度神经网络实现的，但我认为肯定还有其他的解决方案，但是所有的方案都绕不开基于**向量**的处理方式。

只要给定一个维度充分且定义合理的语义空间，原则上任何的事物都可以表示成这个空间中的一个点，这个点在语义空间中的位置可以表示成一个向量，该向量可以用来描述这个事物。比如我们描述一张纸，可以从纸张的形状、颜色、厚度、材质、纹理等维度来构建这个N维语义空间，那么任何一张纸都可以转换成基于此空间的一个N维向量。

LLM中的嵌入也是基于这个思想，当处理的文本被分词器转换成相应的词元后，需要将其转换成基于某个语义空间的向量。但是我们没有能力也没有必要确定这个语义空间每个维度具体表示什么，因为我们不关心某个词源对应向量的每个维度的表示，我们只关心两个向量在语义空间中的距离能否反映对应词元的相似度。假设“猫”、“狗”和“菠菜”这三个词元对应的向量分别为下A、B和C，A与B之间的距离必须小于与C的距离。在线性代数中，向量之间的具体可以采用不同的**范数**来表示，我们最熟悉的欧几里得范数。

对于我们日常获的各种有意义的文本片段，原则上两个词元在同一文本片段一起出现的频率基本能够体现出它们的相似度。那么问题就好解决了，我们只需要确定语义空间的维度数量，然后构建一个用于确定词元对应向量的模型，采用机器学习的方式使用现成的语料（比如爬取的网页内容、出版的图书文本等）训练此模型，训练的目标（损失函数）只有一个：**让相似词元映射在语义空间中的点尽量靠近，反之尽量远离**。

整个过程相当于通过将词元转换成对应的向量，将其**嵌在**语义空间的某个位置，这就是嵌入（Embedding）这一慨念的由来。我们称这个对词元实施向量化的过程为**嵌入**，将这个语义空间成为“嵌入空间”，将词元对应的向量称为**嵌入向量**，有时直接称为**嵌入**。

### 1.1 Embeddings

嵌入在LangChain中通过如下这个名为`Embeddings`的抽象类表示，确切地说，`Embeddings`代表的是实现文本向量化的**嵌入模型**。它定义了`embed_documents`和`embed_query`两个抽象方法，在将指定的一个或者多个文本存储在`VectorStore`之前，我们一般调用前者将其转换成一组通过`list[float]`表示的嵌入向量(列表的长度就是嵌入空间的维度数量)，后者则在对`VectorStore`实施检索之前将查询文本转换成嵌入向量。

```python
class Embeddings(ABC):
    @abstractmethod
    def embed_documents(self, texts: list[str]) -> list[list[float]]
    @abstractmethod
    def embed_query(self, text: str) -> list[float]

    async def aembed_documents(self, texts: list[str]) -> list[list[float]]
    async def aembed_query(self, text: str) -> list[float]
```

`embed_documents`方法所谓的`Document`更多地是指存储在`VectorStore`中的记录。除了这两个同步方法，`Embeddings`还定义了异步方法`aembed_documents`和`aembed_query`，它们会默认调用同步方法，大部分子类都会对它们进行重写。

## 2. VectorStore

在RAG的解决流程中，被切割后的文本会通过`Embeddings`转换成嵌入向量，连同关联的元数据存储到`VectorStore`中。由于`Document`是文本和元数据的复合体，所以`VectorStore`的很多操作都是金基于`Document`进行的。这也是为什么上面介绍的很多分割器类型直接将`Document`对象作为分割后的产物，有的还提供的了方法将指定的文本/对象列表和元数据映射表进行合并生成一组`Document`。由于需要对文本进行向量化，所以作为向量存储基类的`VectorStore`必须拥有一个`Embeddings`对象，它对应着该抽象类的`embeddings`特性。

```python
class VectorStore(ABC):
    @property
    def embeddings(self) -> Embeddings | None
```

### 2.1 向量记录的添加与删除

`VectorStore`提供了一系列方法实现针对向量存储的读写。具体的**写操作**体现在如下所述的三组方法，它们分布实现对存储记录的添加和删除。存储的记录可以通过`get_by_ids`方法提取出来，方法返回的是`Document`的列表。

```python
class VectorStore(ABC):
    def add_texts(
        self,
        texts: Iterable[str],
        metadatas: list[dict] | None = None,
        *,
        ids: list[str] | None = None,
        **kwargs: Any,
    ) -> list[str]
    async def aadd_texts(
        self,
        texts: Iterable[str],
        metadatas: list[dict] | None = None,
        *,
        ids: list[str] | None = None,
        **kwargs: Any,
    ) -> list[str]    
    
    def add_documents(self, documents: list[Document], **kwargs: Any) -> list[str]
    async def aadd_documents(self, documents: list[Document], **kwargs: Any) -> list[str]

    def delete(self, ids: list[str] | None = None, **kwargs: Any) -> bool | None
    async def adelete(self, ids: list[str] | None = None, **kwargs: Any) -> bool | None

    def get_by_ids(self, ids: Sequence[str], /) -> list[Document]
```

三组方法说明如下：

- **add_texts/aadd_texts**：需要以可迭代对象和列表形式提供文本和元数据，如果没有通过`ids`参数提供输入记录的标识（相当于数据记录的主键），方法会自动创生成标识。方法的返回添加记录的ID列表；
- **add_documents/aadd_documents**：它以`Document`的形式提供添加记录的文本和元数据；
- **delete/adelete**：删除指定ID列表对应的记录，方法返回是否成功的布尔值。在生产环境下，如果原始文档更新了，我们需要先根据ID删除旧的分块，再重新插入新的，否则会导致检索到过期信息；

```python
class VectorStore(ABC):
    @classmethod

        embedding: Embeddings,

        ids: list[str] | None = None,

    ) -> VST

    @classmethod
    async def afrom_texts(
        cls,
        texts: list[str],
        embedding: Embeddings,

```

上面定义的这两组类方法（`from_documents/afrom_documents`和`from_texts/afrom_texts`）同时完成了针对`VectorStore`的创建和数据的添加，其中`from_texts`是具体向量存储类型必须实现的抽象方法。

### 2.2 普通相似度检索

将关联元数据的切片存入`VectorStore`不是我们的目的，我们最终目的是能够根据用户指定的基于自然语言的查询文本对其实施检索，返回相关的记录的元数据。传统关系型和NonSQL提供的文本查询只能完成基于**是否包含指定字符**检索，`VectorStore`提供的是基于两个向量的相似度查询。如果两个对象能够使用同一个描述空间的向量来表示，它们之间的相似度可以利用向量之间的距离来表示。采用不同的范数，向量**距离**具有不同的计算方式，我们`VectorStore`通常使用如下两种计算方式：

- **欧氏距离**：嵌入空间两个点的物理距离；距离越短，相似度越高；
- **余弦距离**：不看物理距离，只看向量的方向。如果将两个向量的夹角表示成θ，可以使用`cosine(θ)`的表达式来表示距离。由于`cosine`是θ的减函数，本着相似度与距离成反向关系的原则，我们将`(1 - cosine(θ))`作为余弦距离。`cosine(θ)`表示余弦相似度；

在大规模向量检索中，余弦相似度比欧氏距离更受欢迎，主要有以下几个核心原因。

- **关注语义而非长度**：在Embedding 模型中，向量的方向代表了语义特征，而向量的长度往往受文本长度或高频词影响，难以真正反映语义相关性。余弦相似度只看夹角，即使两段话长度不同，只要意思接近，它们的余弦值就会很高；
- **归一化特性**：余弦相似度的结果始终在`[-1, 1]`之间（在Embedding中通常是[0, 1]）。这种标准化的范围让开发者更容易设定阈值来过滤低相关性的结果。相比之下，欧氏距离的数值范围是` [0, ∞)`，很难直观判断多远才算**不相关**；
- **计算效率高**：当向量经过归一化处理后，余弦相似度的计算可以简化为两个向量的点积。点积在现代CPU和GPU上都有极高的硬件加速效率，非常适合处理千万级以上的数据检索；
- **高维空间的鲁棒性**：在高维空间中，点与点之间的欧氏距离往往会趋于相等（即“维度灾难”），导致区分度下降。而余弦相似度通过对比角度，在处理这种稀疏或高维语义空间时表现更稳定；

所在很多具体的`VectorStore`（比如`InMemoryVectorStore`）都默认使用余弦相似度。

#### 2.2.1 基于向量的查询

将查询文本转换成向量后，可以调用如下所示的`similarity_search_by_vector`/`asimilarity_search_by_vector`方法实施相似度查询，查询结果以`Document`列表的形式返回。`VectorStore`并没有真正实现`similarity_search_by_vector`方法，`asimilarity_search_by_vector`仅仅是以Coroutine的形式调用了该方法（以下介绍的异步方法基本采用这样的实现方式），所以具体的子类需自行实现此方法。

但是`VectorStore`将针对`similarity_search_by_vector`方法的实现下放给了子类。

```python
class VectorStore(ABC):    
    def similarity_search_by_vector(self, embedding: list[float], k: int = 4, **kwargs: Any) -> list[Document]:
        raise NotImplementedError

    async def asimilarity_search_by_vector(self, embedding: list[float], k: int = 4, **kwargs: Any) -> list[Document]:
        return await run_in_executor(None, self.similarity_search_by_vector, embedding, k=k, **kwargs)
```

上述两个方法包含如下的参数：

- **embedding**：原始查询文本转换成的查询向量；
- **k**：指定返回最相似的`Document`数量。如果k太小（如1），LLM可能拿不到足够的信息；如果k太大（如20），可能会引入无关噪音并浪费Token。通常3-5是平衡点，所有的查询方法都有此参数；
- **kwargs**：通常用来传递元数据过滤器。例如，只在`source='manual_v2.pdf'`的范围内进行相似度搜索；

#### 2.2.2 基于文本的查询

`similarity_search`/`asimilarity_search`方法的相似性查询直接针对原始的查询文本进行，其内部会利用`Embeddings`对象对其向量化。`similarity_search`被定义成必须实现的抽象方法。

```python
class VectorStore(ABC):
    @abstractmethod
    def similarity_search(self, query: str, k: int = 4, **kwargs: Any) -> list[Document]
    async def asimilarity_search(self, query: str, k: int = 4, **kwargs: Any) -> list[Document]
```

#### 2.2.3 返回相似度分数

如下所示的`similarity_search_with_score`/`asimilarity_search_with_score`除了返回`Document`之外，还会返回一个相似度分数。一般来说，我们使用这个方法返回原始的分数，比如上述的两种**距离**。由于很多类型的距离是没有范围限制的，基于不同尺度的得分其实没有什么意义，所以我们更希望得到一个**归一化**的得分，`VectorStore`为此定义了`similarity_search_with_relevance_scores`/`asimilarity_search_with_relevance_scores`。这两个方法返回的**相关性得分**限定在[0,1]之间，分数越高，相关性越强。

```python
class VectorStore(ABC):
    def similarity_search_with_score(
        self, *args: Any, **kwargs: Any
    ) -> list[tuple[Document, float]]
    async def asimilarity_search_with_score(
        self, *args: Any, **kwargs: Any
    ) -> list[tuple[Document, float]]

    def similarity_search_with_relevance_scores(
        self,
        query: str,
        k: int = 4,
        **kwargs: Any,
    ) -> list[tuple[Document, float]]
    async def asimilarity_search_with_relevance_scores(
        self,
        query: str,
        k: int = 4,
        **kwargs: Any,
    ) -> list[tuple[Document, float]]
```

`similarity_search_with_relevance_scores`/`asimilarity_search_with_relevance_scores`默认会调用`similarity_search_with_score`/`asimilarity_search_with_score`方法，并使用如下这个`_select_relevance_score_fn`方法对后者返回的分数实施会归一化。由于`_select_relevance_score_fn`方法并没有真正被实现，若子类没有重写此方法，调用这两个方法会抛出异常。`VectorStore`提供了`_euclidean_relevance_score_fn`和`_cosine_relevance_score_fn`这两个静态方法对欧式距离和余弦距离进行归一化，我们可以根据当前采用的相似度算法利用它们来实现`_select_relevance_score_fn`方法。

```python
class VectorStore(ABC):
    @staticmethod
    def _euclidean_relevance_score_fn(distance: float) -> float:
        return 1.0 - distance / math.sqrt(2)
    @staticmethod
    def _cosine_relevance_score_fn(distance: float) -> float:
        return 1.0 - distance    
    def _select_relevance_score_fn(self) -> Callable[[float], float]:
        raise NotImplementedError
```

### 2.3 最大边界相关性检索

普通的相似度查询采用**K-最近邻算法（KNN：K-Nearest Neighbors）**只会找最像的，容易导致搜出来的几条内容高度重复。为了保证相关性的同时让结果更具多样化，可以采用**最大边界相关性（MMR：Max Marginal Relevance）算法**。举个例子，假设我们的查询条件是：“如何评价周杰伦的音乐？”

- **KNN检索**：可能给你找回5条都在夸他**中国风**的段落。信息冗余，浪费了LLM的上下文窗口。
- **MMR检索**：会先选一条讲**中国风**的，第二条发现也是讲**中国风**的（太像了，剔除），转而选一条讲**编曲技巧**的，第三条选讲**社会影响**的。

MMR在挑选每一条文档时，会权衡两个指标：

- **相关性 (Relevance)**：这条文档离我的问题有多近？
- **多样性 (Diversity)**：这条文档和已经选出来的文档是不是太像了？

MMR公式中有一个关键系数λ（通常在0到1之间），默认值（通常为 0.5）在相关性和多样性之间取得平衡：

- λ = 1：完全等同于普通的相似度搜索（只看相关性）;
- λ = 0：完全追求多样性（选出来的东西互不相同，哪怕离问题有点远）。

如果需要使用MMR查询，可以调用`VectorStore`的如下两组方法：`max_marginal_relevance_search`/`amax_marginal_relevance_search`和`max_marginal_relevance_search_by_vector`/`amax_marginal_relevance_search_by_vector`。`max_marginal_relevance_search`和`max_marginal_relevance_search_by_vector`依然没有被真正实现，提供MMR检索功能的子类需要重写它们。

```python
class VectorStore(ABC):
     def max_marginal_relevance_search(
        self,
        query: str,
        k: int = 4,
        fetch_k: int = 20,
        lambda_mult: float = 0.5,
        **kwargs: Any,
    ) -> list[Document]:
        raise NotImplementedError

    async def amax_marginal_relevance_search(
        self,
        query: str,
        k: int = 4,
        fetch_k: int = 20,
        lambda_mult: float = 0.5,
        **kwargs: Any,
    ) -> list[Document]

    def max_marginal_relevance_search_by_vector(
        self,
        embedding: list[float],
        k: int = 4,
        fetch_k: int = 20,
        lambda_mult: float = 0.5,
        **kwargs: Any,
    ) -> list[Document]:
        raise NotImplementedError

    async def amax_marginal_relevance_search_by_vector(
        self,
        embedding: list[float],
        k: int = 4,
        fetch_k: int = 20,
        lambda_mult: float = 0.5,
        **kwargs: Any,
    ) -> list[Document]
```

如下是相关参数说明：

- **query/embedding**：查询文本或者嵌入向量；
- **k**: 最终选择记录数；
- **fetch_k**：MMR检索的候选记录是KNN检索的结果，该参数表示此检索结果的记录数；
- **lambda_mult**: 上述的系数λ；

### 2.4 统一收口

对于上面实现的众多形式的相似度查询方法，`VectorStore`定义了如下的`search`/`asearch`方法来统一收口，我们可以利用`search_type`参数决定具体调用的方法。

```python
class VectorStore(ABC):
    def search(self, query: str, search_type: str, **kwargs: Any) -> list[Document]:
        if search_type == "similarity":
            return self.similarity_search(query, **kwargs)
        if search_type == "similarity_score_threshold":
            docs_and_similarities = self.similarity_search_with_relevance_scores(
                query, **kwargs
            )
            return [doc for doc, _ in docs_and_similarities]
        if search_type == "mmr":
            return self.max_marginal_relevance_search(query, **kwargs)
        msg = (
            f"search_type of {search_type} not allowed. Expected "
            "search_type to be 'similarity', 'similarity_score_threshold'"
            " or 'mmr'."
        )
        raise ValueError(msg)

    async def asearch(self, query: str, search_type: str, **kwargs: Any) -> list[Document]
```

`search_type`参数具有如下三个选项：

- **similarity**：调用`similarity_search`/`asimilarity_search`方法；
- **similarity_score_threshold**：调用`similarity_search_with_relevance_scores`/`asimilarity_search_with_relevance_scores`方法；
- **mmr**：调用`max_marginal_relevance_search`/`amax_marginal_relevance_search`方法；

## 3. 自定义VectorStore

在如下的演示程序中，我们继承`VectorStore`定义了一个`SimpleVectorStore`类。构造函数除了指定`Embeddings`对象之外，还利用`similarity`参数指定了采用的相似度算法（基于欧式距离或者余弦距离）。根据指定的算法，我们定义相应的函数`dist_fn`用来计算两个嵌入向量的距离，并对用来计算归一化相关分数的`_select_relevance_score_fn`函数进行了相应设置。

```python
from typing import Any, Iterable,NamedTuple,Callable,Literal, Self,Literal
import uuid
from dotenv import load_dotenv
from langchain_core.documents import Document
from typing_extensions import override
from langchain_openai import OpenAIEmbeddings
from langchain_core.vectorstores import VectorStore,InMemoryVectorStore
from langchain_core.embeddings import Embeddings
from itertools import islice
import math

load_dotenv()
Vector = list[float]
class Record(NamedTuple):
    id:str
    vector:list[float]
    text:str
    metadata:dict[str,Any]

class SimpleVectorStore(VectorStore):    
    store: list[Record] = []
    dist_fn:Callable[[Vector,Vector],float]

    def __init__(self, embedding: Embeddings, similarity:Literal["cosine","euclidean"] ="cosine") -> None:
        def cosine_dist(v1: Vector, v2: Vector) -> float:
            import numpy as np  
            norm_v1 = np.linalg.norm(v1)
            norm_v2 = np.linalg.norm(v2)
            return 1- np.dot(v1, v2) / (norm_v1 * norm_v2)

        self.embedding = embedding
        if similarity == "euclidean":
            self.dist_fn = lambda v1, v2: math.dist(v1, v2)
            self._select_relevance_score_fn = lambda : self._euclidean_relevance_score_fn
        else:
            self.dist_fn = cosine_dist
            self._select_relevance_score_fn = lambda : self._cosine_relevance_score_fn

    def add_texts(
        self,
        texts: Iterable[str],
        metadatas: list[dict] | None = None,
        *,
        ids: list[str] | None = None,
        **kwargs: Any,
    ) -> list[str]:
        count = sum(1 for _ in texts)
        metadatas = metadatas or [{}] * count
        ids = ids or [str(uuid.uuid4()) for _ in range(count)]
        for id, text, metadata in zip(ids, texts, metadatas):
            vector = self.embedding.embed_query(text)
            self.store.append(Record(id=id, vector=vector, text=text, metadata=metadata))
        return ids
    
    def similarity_search(self, query: str, k: int = 4, **kwargs: Any) -> list[Document]:
        result = self.similarity_search_with_score(query, k=k, **kwargs)
        return [doc for doc, score in result]
    
    @override
    def similarity_search_with_score(self, query: str, k: int = 4, **kwargs: Any) -> list[tuple[Document, float]]:
        query_embedding = self.embedding.embed_query(query)
        filter = lambda it: all(it.metadata.get(k) == v for k, v in kwargs.items())
        selected = (it for it in self.store if filter(it))
        result = ((it, self.dist_fn(query_embedding, it.vector)) for it in selected)
        top_k = islice(sorted(result, key=lambda x: x[1]), k)
        return [(Document(page_content=it.text, metadata=it.metadata), score) for it, score in top_k]

    @classmethod
    @override
    def from_texts(
        cls,
        texts: list[str],
        embedding: Embeddings,
        metadatas: list[dict] | None = None,
        similarity:Literal["cosine","euclidean"] ="cosine",
        **kwargs: Any,
    ) -> Self:
        store = cls(
            embedding=embedding, 
            similarity=similarity,
        )
        store.add_texts(texts=texts, metadatas=metadatas, **kwargs)
        return store
```

实现的`add_texts`方法将指定的文本、ID和元数据列表转换成对应的`Record`元组，如果没有指定ID，则使用生成的UUID。`Record`元组被置于表示存储的`store`字段，这是一个普通的列表。我们重写了`similarity_search_with_score`方法，根据指定的关键字参数对记录进行过滤。在为指定的查询文本生成嵌入向量后，我们利用`dist_fn`字段返回的函数计算相似度距离。我们最后按照此距离对过滤记录进行排序，提取前K条记录生成返回的`(Document, Distance)`元组列表。实现的`similarity_search`方法直接调用此方法，将`Document`提取出来作为返回值。

我们使用如下的程序来验证`SimpleVectorStore`提供的相似对检索是否合理。我们使用的是`OpenAIEmbeddings`，添加的两条记录是两条针对“美食”和“运动”喜好的文本，而作为查询的是针对前者的查询，所以我们希望前者与查询的相似度更大。我们分别针对两种相似度算法创建了`SimpleVectorStore`对象，并调用了`similarity_search_with_score`和`similarity_search_with_relevance_scores`方法看看两条记录与查询文本的“相似度距离”和“相关性得分”。

```python
embedding=OpenAIEmbeddings(model="text-embedding-3-small")
texts=[
        "I love eating spicy Sichuan food.",
        "My favorite sport is swimming."]
query = "What are my food preferences?"

print(f"euclidean similarity:")
store = SimpleVectorStore.from_texts(
    texts=texts,
    embedding=embedding,
    metadatas=[{"category": "food"}, {"category": "sport"}],
    similarity = "euclidean"
)
result = store.similarity_search_with_score(query, k=2)
for doc, score in result:
    print(f"Raw score: {score:.4f}, Content: {doc.page_content}")

result = store.similarity_search_with_relevance_scores(query, k=2)
for doc, score in result:
    print(f"Relevance score: {score:.4f}, Content: {doc.page_content}")

print(f"cosine similarity:")
store = SimpleVectorStore.from_texts(
    texts=texts,
    embedding=embedding,
    metadatas=[{"category": "food"}, {"category": "sport"}],
    similarity = "cosine"
)
result = store.similarity_search_with_score(query, k=2)
for doc, score in result:
    print(f"Raw score: {score:.4f}, Content: {doc.page_content}")

result = store.similarity_search_with_relevance_scores(query, k=2)
for doc, score in result:
    print(f"Relevance score: {score:.4f}, Content: {doc.page_content}")
```
