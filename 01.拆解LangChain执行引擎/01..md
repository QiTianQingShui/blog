# [拆解LangChain执行引擎]以Actor模型的视角来看Pregel

利用`LangChain`开发的Agent可以看成是一个具有状态的、由节点（Node）和边（Edge）组成的**有向有环图** ，具体体现为一个`StateGraph`对象。`StateGraph`对象经过编译的生成一个`Pregel`对象，这是一个由节点（Node）和通道（Channel）构成的**Actor模型**。此模型中的的Actor就是绑定一个执行函数的节点，其状态维护在各种类型的通道中。通道不仅仅为节点提供输入并接收执行结果，它还是驱动节点执行的信号源。

## 1. Agent、StateGraph和Pregel的关系

接下来我们通过如下的演示程序来说明`Agent`、`StateGraph`和`Pregel`三者之间的关系。这是一个由两个节点组成的帮助我们生成笑话的Agent:

- 第一个节点会利用LLM生成一个基于指定的主题的笑话；
- 评估生成的笑话，返回 **good** 或者 **bad** ；
- 如果评估失败，调用另一个节点生成一个具有更高质量的笑话；

`JokeAgentState`是承载了贯穿整个 **笑话生产线** 的状态类型，状态成员对应的字段包括：

- `topic`：笑话的主题；
- `init_joke`：第一个生成的笑话；
- `review`：对第一个笑话的评估结果；
- `improved_joke`：重新生成的笑话。

两个生产笑话的节点绑定到`generate_joke`和 `regenerate_joke`函数，这两个函数从作为参数的`JokeAgentState`对象中读取输入，在执行完相应操作之后，通过返回的字典的形式以增量的形式写入对应的输出通道。

```python
from langchain_openai import ChatOpenAI
from typing import TypedDict, Literal
from langgraph.graph import StateGraph, START, END
from langgraph.pregel import Pregel

class JokeAgentState(TypedDict):
    topic: str
    review: Literal["good", "bad"]
    init_joke: int
    improved_joke: str

model = ChatOpenAI(
    model="gpt-5.2-chat",
    base_url="URL for your own deployed model",
    api_key="your own api key"
)

def generate_joke(state: JokeAgentState):
    """
    调用LLM生成一个关于指定主题的笑话。
    """
    result = model.invoke(f"写一个关于{state['topic']}的笑话，要求在50字以内")
    return {"init_joke": result.content}

def regenerate_joke(state: JokeAgentState):
    """
    原笑话不好笑，重新生成一个笑话。
    """
    result = model.invoke(f"之前生成的笑话没意思，请重新一个{state['topic']}的笑话，原笑话是：{state['init_joke']}")
    return {"improved_joke": result.content}

builder = (
    StateGraph(JokeAgentState)
    .add_node("generate_joke", generate_joke)
    .add_node("regenerate_joke", regenerate_joke)
)

builder.add_edge(START, "generate_joke")
builder.add_edge("regenerate_joke", END)
builder.add_conditional_edges(
    "generate_joke", lambda _: "bad", {"good": END, "bad": "regenerate_joke"}
)

agent: Pregel = builder.compile()
result: JokeAgentState = agent.invoke({"topic": "猫"})
print(result["init_joke"])
print(result["improved_joke"])
```

在根据类型`JokeAgentState`创建出`StateGraph`对象后，我们调用`add_node`方法添加了由`generate_joke`和`regenerate_joke`函数绑定的节点。接下来我们调用`add_edge`添加了开始节点到`generate_joke`节点以及`regenerate_joke`节点到终止节点的两条静态边。由于`generate_joke`节点执行后是结束还是继续执行`regenerate_joke`节点，依赖于评估的结果，我们调用`add_conditional_edges`方法在它们之间添加了条件边。为了走完全程，我们是使模拟评估的Lambda表达式直接返回`bad`。最终构建的，代表状态图的StateGraph具有如下的拓扑结构。实际上下面这张图就是由`StateGraph`对象直接生成的。

![Screenshot 2026-02-01 151834.png](https://upload-images.jianshu.io/upload_images/30993788-5fcb56f5d5b01bbb.png?imageMogr2/auto-orient/strip%7CimageView2/2/w/1240)

`StateGraph`不是Agent，仅仅是构建Agent的Builder，所以我们调用`StateGraph`对象的`compile`方法将Agent **编译** 出来。然后我们以字典形式指定笑话的主题（ “猫” ），调用Agent对象的`invoke`方法开启这个笑话生产线，得到的结果就是作为全局状态的`JokeAgentState`对象。我们将两次生成的笑话打印出来，就是如下所示的结果。

```python
我家猫减肥失败，因为每次跑步都追着激光笔吃夜宵。

好，那我换一个更有梗的：

我家猫最近开始冥想，

每天对着墙坐半小时。

我以为它在修行，

结果它只是在等墙里的“看不见的小虫”出来。
```

作为编译结果的Agent就是一个`Pregel`对象，后者代表了Agent这个**执行体**，所以我们才说`Pregel`是整个LangChain的执行引擎。`StateGraph`是一张图（Graph，专指图论语境中的“图”），但是`Pregel`却是一个Actor模型。我们采用图的方式来构建Agent，因为图是更易于 **人脑** 理解的形式，这使Agent编程变得很简单；我们将它编译成基于Actor模型的执行体，是因为这是 **电脑** 更易于处理的形式，使得执行起来更加快捷可靠。

从这个意义上将，`StateGraph`和`Pregel`可以认为是Agent在不同视角的表现形式。`StateGraph`对应的图是Agent的概念视图；而`Pregel`对应的Actor模型是Agent的执行视图。虽然单纯的编程工作可以不用过多地涉及`Pregel`，但是如果想对LangChain这一平台具有深刻地认知，我觉得彻底地搞清楚`Pregel`是很有意义的。

## 2.基于Pub/Sub的驱动执行

作为Pregel这个Actor模型的核心，表示节点的`PregelNode`对象是一个单纯的无状态执行体，它定义了如下三个核心字段成员：

```python
class PregelNode:
    channels : str | list[str]
    triggers     : list[str]
    bound     : Runnable[Any, Any]
    …
```

三个核心字段说明如下：

-**channels**：表示提供输入的Channel列表，Node的执行会读取这些Channel的值作为输入；
-**triggers**：表示触发当前Node执行的Channel列表，列表中的任一Channel具有变更都会触发当前Node的执行；
-**bound**：表示绑定的可执行对象，类型为`Runnable[Any, Any]`，用于定义Node的具体操作逻辑。

节点是无状态的，所以Pregel的状态维护自然就落在通道上面。通道不仅维护Pregel对象执行过程中的状态，还作为输入和输出的渠道。针对通道的写入会改变Pregel的状态，同时触发该状态的变更事件，节点通过订阅目标通道的变更事件来触发自身的执行。整个Pregel对象的执行就是一个基于Pub/Sub模式的事件驱动过程。

在如下这个演示实例中，我们定义了一个由一个节点和两个通道构建的Pregel对象。如代码片段所示，我们创建了一个`PregelNode`对象，并将其`channels`和`triggers`字段设置为`input`，意味着`input`通道的变更将会触发节点的执行，并为其提供输入数据。我们将它的`bound`字段指定为一个`RunnableLambda`对象上，它承载的操作体现在指定的Lambda表达式上，它没有过的的操作，直接返回原始输入。

```python
from langgraph.channels import LastValue
from langgraph.pregel import Pregel
from langgraph.pregel import Pregel
from langgraph.channels import LastValue
from langgraph.pregel._read import PregelNode
from langchain_core.runnables import RunnableLambda
from langgraph.pregel._write import ChannelWrite, ChannelWriteEntry

node = PregelNode(
    channels="input",
    triggers=["input"],
    bound=RunnableLambda(lambda args: args))

channelWrite:ChannelWrite = ChannelWrite(writes=[ChannelWriteEntry(channel="output")])
node.writers.append(channelWrite)

app = Pregel(
    nodes={"body": node},
    channels={"input": LastValue(str), "output": LastValue(str)},
    input_channels=["input"],
    output_channels=["output"],
)

result = app.invoke(input={"input": "foobar"})
assert result == {"output": "foobar"}
```

节点执行的结果，需要利用`writer`字段提供的**写入器**输出到对应的通道。在这里我们使用的是一个`ChannelWrite`对象，针对目标通道（命名为`output`）的写入意图以`ChannelWriteEntry`对象的形式定义，并添加到`ChannelWrite`的`writes`列表中。我们创建了一个Pregel对象，并将其`nodes`和`channels`字段分别指定为表示节点和通道的字典，其Key为节点/通道的名称。LangGraph为我们定义了一系列不同类型的通道，这里我们指定的通道类型为`LastValue`，作为构造函数参数指定的类型（`str`）为通道存储的数据类型。我们通过设置`input_channels`和`output_channels`字段为Pregel对象的指定了输入和输出通道。

我们直接调用Pregel对象的`invoke`方法启动执行流程，输入参数`input`以字典的形式初始化每个输入通道（此时只有`input`通道）。`input`通道的写入将自动触发节点的执行，它会读取此通道的值（`foobar`），执行完成之后将执行结果（`foobar`）写入命名为`output`的通道。整个流程执行完毕，所有注册的输出通道的值将被读取出来，并以字典的形式作为`invoke`方法的返回值，对应的Key就是输出通道的名称，所以断言揭示了执行的结果为`{"output": "foobar"}`。

## 3. 利用NodeBuilder构建PregelNode

上面的例子直接`__init__`方法创建作为节点的`PregelNode`对象。`PregelNode`类的包名为`langgraph.pregel._read`，为了初始化其`writers`字段，我们还需要从`langgraph.pregel._write`中导入`ChannelWrite`和`ChannelWriteEntry`类，从包的命名就可以看出这并不是典型的编程方式。在绝大部分情况下我们会利用`NodeBuilder`采用**Builder模式**来初始化节点。利用`NodeBuilder`将会是我们的代码变得格外简单：

```python
from langgraph.channels import LastValue
from langgraph.pregel import Pregel, NodeBuilder

node = (NodeBuilder()
    .subscribe_only("input")
    .do(lambda args: args)
    .write_to("output")
    .build())

app = Pregel(
    nodes={"body": node},
    channels={"input": LastValue(str), "output": LastValue(str)},
    input_channels=["input"],
    output_channels=["output"],
)

result = app.invoke(input={"input": "foobar"})
assert result == {"output": "foobar"}
```

在上述结构该井的代码中，我们在创建了`NodeBuilder`对象之后：

- 调用了它的`subscribe_only`方法指定了唯一的输入通道；
- 调用`do`方法会为利用指定的Lambda表达式创建对应的`RunnableLambda`对象，并设置为`PregelNode`的`bound`字段；
- 调用`write_to`方法创建并注册相应的`ChannelWrite`，它将执行结果写入指定的输出Channel。

实际上这里还可以直接按照如下的方式传入`NodeBuilder`对象，`Pregel`对象在初始化的时候会利用它来构建节点：

```python
node = (NodeBuilder()
    .subscribe_only("input")
    .do(lambda args: args)
    .write_to("output"))

app = Pregel(
    nodes={"body": node},
    channels={"input": LastValue(str), "output": LastValue(str)},
    input_channels=["input"],
    output_channels=["output"],
)
```

## 4. 多通道的读写

上面演示的都是针对单一通道的读写，多通道的读写可以通过不同的编程模式来实现。在如下这段演示程序中，我们为构建的Pregel提供了四个分别命名为`foo`、`bar`、`baz`和`qux`的通道，前两个作为输入，后两个作为输出。节点的处理函数`handle`定义了一个字典类型的参数，它携带了从所有输入通道读取的数据，Key为通道名称。

```python
from langgraph.channels import LastValue
from langgraph.pregel import Pregel, NodeBuilder
from typing import Any

def handle(state:dict[str,Any])->dict[str,Any]:
    foo: str = state["foo"]
    bar: str = state["bar"]
    return{"baz":foo, "qux":bar}

node = (NodeBuilder()
    .subscribe_to("foo", "bar")
    .do(handle)
    .write_to(baz=lambda r: r["baz"], qux=lambda r: r["qux"]))

app = Pregel(

nodes={"body": node},
channels={
    "foo": LastValue(str),
    "bar": LastValue(str),
    "baz": LastValue(str),
    "qux": LastValue(str)},
    input_channels=["foo", "bar"],
    output_channels=["baz", "qux"],
)

result = app.invoke(input={"foo": "abc", "bar": "xyz"})
assert result == {"baz": "abc", "qux": "xyz"}
```

我们希望节点将`foo`和`bar`通道读取的数据分别写入`baz`和`qux`通道，为此我们让`handle`函数返回一个将输出通道名称作为Key的字典。我们直接将`handle`函数作为`do`方法的参数，它会基于此函数创建一个`RunnableCallable`对象，并绑定到构建的节点上。`handle`函数返回的字典将作为在`write_to`方法指定的两个Lambda表达式的输入，指定的关键字参数名（`baz`和`qux`）将作为输出通道的名称，对应的值就是Lambda表达式的返回值。

如果在调用`write_to`方法时直接指定了多个通道， Pregel会将返回结果的字典作为一个整体，同时写入指定的多个目标通道，这相当于在进行针对多通道的消息广播。

```python
from langgraph.channels import LastValue
from langgraph.pregel import Pregel, NodeBuilder
from typing import Any

def handle(state:dict[str,any])->dict[str,Any]:
    foo: str = state["foo"]
    bar: str = state["bar"]
    return{"baz":foo, "qux":bar}

node = (NodeBuilder()
    .subscribe_to("foo", "bar")
    .do(handle)
    .write_to("baz", "qux"))

app = Pregel(
    nodes={"body": node},
channels={
    "foo": LastValue(str),
    "bar": LastValue(str),
    "baz": LastValue(str),
    "qux": LastValue(str)},
    input_channels=["foo", "bar"],
    output_channels=["baz", "qux"],
)

result = app.invoke({"foo": "abc", "bar": "xyz"})
assert result == {"baz": **{"baz": "abc","qux":"xyz"}, "qux": {"baz": "abc","qux":"xyz"}}
```

多通道的写入还可以利用`ChannelWriteEntry`对象来完成（实际上面在`write_to`方法中直接指定的通道名称都会转换成`ChannelWriteEntry`对象），它帮助我们对通道的写入形式进行细粒度的控制。在如下的代码片段中，我们为`ChannelWriteEntry`的`mapper`字段指定了一个Lambda表达式，它会帮我们完成原始的执行结果与输出到通道的真实数据之间的映射。

```python
from langgraph.pregel._write import ChannelWriteEntry
…
node = (NodeBuilder()
    .subscribe_to("foo", "bar")
    .do(handle)
    .write_to(
        ChannelWriteEntry(channel="baz", mapper=lambda r: r["baz"]),
        ChannelWriteEntry(channel="qux", mapper=lambda r: r["qux"]),
))
…
```

有时我们并不希望节点的处理函数使用单一字典这种过于“笼统”的参数，而是倾向于使用输入通道的名称来命名其参数，此时我们可以按照如下的方式利用**拆包**来解决这个。

```python
def handle(foo:str, bar:str)->dict[str,Any]:
    return{"baz":foo, "qux":bar}

node = (NodeBuilder()
    .subscribe_to("foo", "bar")
    .do(lambda state: handle(**state))
    .write_to(
        ChannelWriteEntry(channel="baz", mapper=lambda s: s["baz"]),
        ChannelWriteEntry(channel="qux", mapper=lambda s: s["qux"]),
    ))
```

## 5.Node之间的依赖

LangChain构建的Agent本质上是一个图模型（Graph模型）。我们利用模型和工具节点构建的Agent虽然看起来像是一个有始无终的有环图，但是它本质上是一个`StateGraph`对象，后者是由节点（Node）和边（Edge）构成的有始（`__start__`节点）有终（`__end__`节点）的图，边体现了由它连接两个Node之间的依赖关系。StateGraph对象最终通过编译转换成Pregel对象后，Edge体现的依赖关系被转换成**节点基于通道的订阅/发布关系**。

假设A和B是StateGraph的两个节点，A到B的StateGraph表示B必须等到A执行完成后才能执行，即B依赖于A。在Pregel中并没有边的概念，节点之间的依赖关系只能利用针对通道的订阅/发布来实现。具体实现其实很简单：让A在执行完成后向B订阅的通道写入触发信号。

在如下所示的演示程序中，我们定义了一个名为`output`类型为`BinaryOperatorAggregate`的通道。顾名思义，这个通道类型利用指定的二元操作对当前值和新写入的值进行聚合，最终确定最新的内容。我们利用它来存储一个字符串来表示按序执行的节点列表，所以我们在创建它的时候以Lambda表达式指定了这个二元操作符，后者将添加的节点名称作为后缀（“，{node}”）附加到当前内容上。

我们为创建的Pregel对象创建了三个命名为`foo`、`bar`和`baz`的节点，以及对应的触发通道，也就是三个节点订阅对应的通道。我们将`foo`通道作为输入，在调用的时候指定，所以`foo`节点率先执行。每个节点执行完后（这里没有执行任何具体的操作，可以任务是一个空操作），除了将自身的名称写入`output`通道之外，还需要写入相应的通道驱动后续节点的执行（`foo`执行完后写入`bar`，`bar`执行完之后写入`baz`）。

```python
from langgraph.channels import LastValue,BinaryOperatorAggregate
from langgraph.pregel import Pregel, NodeBuilder

foo = (NodeBuilder()
       .subscribe_to("foo",read=False)
       .write_to(output="foo", bar=None))
bar = (NodeBuilder()
       .subscribe_to("bar",read=False)
         .write_to(output="bar", baz=None))
baz = (NodeBuilder()
       .subscribe_to("baz",read=False)
       .write_to(output="baz"))

app = Pregel(
    nodes={
        "foo":foo,
        "bar":bar,
        "baz":baz
    },
    channels={
        "foo": LastValue(None),
        "bar": LastValue(None),
        "baz": LastValue(None),
        "output": BinaryOperatorAggregate(str, operator=lambda a,b: f"{a},{b}")
    },
    input_channels=["foo"],
    output_channels=["output"]
)

result = app.invoke({"foo": None})
assert result == {"output": ",foo,bar,baz"}
```

## 6. 多节点依赖

对一个节点来说，只要它的`triggers`列表中任何一个通道有更新，它就会被驱动执行。如果采用上面例子演示的驱动方式，当某个节点具有多个作为前置条件的节点，任何一个作为前置条件的节点执行完后，自己就会被动执行一次。也就说前置节点和它之间是一种**ANY**的驱动关系，如何实现 **ALL** 的驱动关系呢？即所有前置节点都执行完毕才满足后续节点的执行条件。以如下这张图为例，开始的时候以两个分支并行执行，左边分支先后执行`foo`和`baz`，右边分支执行`bar`。我们要求`baz`和`bar`都成功执行后，`qux`才能执行。

![Untitled.png](https://upload-images.jianshu.io/upload_images/30993788-55055cfdddc68257.png?imageMogr2/auto-orient/strip%7CimageView2/2/w/1240)

这个问题有两种解决方案，一种就是让`baz`和`bar`完成执行后利用通道写入的方式向`qux`发送一个信号，同时将自己已经完成的状态通过相应的通道保存下来。这样`qux`会被触发两次，但是它可以读取对应的通道判断前置条件是否满足。在如下的实现中，我们依然为四个节点设置了触发它们的同名通道。由于`foo` 和 `bar` 这两个节点最开始并行执行，我们将对应的通道设置为输入通道。我们为Pregel注册了另一个名为 `output` 的输出通道用于收集成功执行的通道。此通道依然为`BinaryOperatorAggregate`，但与之前不同的是其数据类型被设置为列表，并利用`operator.add`将新的通道名称加入列表。

```python
from langgraph.channels import LastValue,BinaryOperatorAggregate
from langgraph.pregel import Pregel, NodeBuilder
import operator
from typing import Any

foo = (NodeBuilder()
    .subscribe_to("foo",read=False)
    .write_to(output=["foo"], baz=None))
bar = (NodeBuilder()
    .subscribe_to("bar",read=False)
    .write_to(output=["bar"], qux=None))
baz = (NodeBuilder()
       .subscribe_to("baz",read=False)
       .write_to(output=["baz"], qux=None))

def handle(args:dict[str,Any]):
    output:list[str] = args["output"]
    **if "bar" in output and "baz" in output:
        return ["qux"]
    return []**

qux = (NodeBuilder()
       .subscribe_to("qux",read=False)
       .read_from("output")
       .do(handle)
       .write_to("output"))

app = Pregel(
    nodes={
        "foo":foo,
        "bar":bar,
        "baz":baz,
        "qux":qux
    },
    channels={
        "foo": LastValue(None),
        "bar": LastValue(None),
        "baz": LastValue(None),
        "qux": LastValue(None),
        "output": BinaryOperatorAggregate(list, operator=operator.add)
    },
    input_channels=["foo","bar"],
    output_channels=["output"]
)

result = app.invoke({"foo": None, "bar": None})
sequences:list[list[str]] = [
    ["foo","baz","bar","qux"],
    ["bar","foo","baz","qux"],
    ["foo","baz","bar","qux"]]
assert result["output"] in sequences
```

我们依然按照上一个实例的套路：每个节点在完成执行后都将自己的名称写入`output`通道。我们在调用Pregel的时候通过对 `foo` 和 `bar` 这两个通道的写入驱动对应节点的执行。 `foo`、`bar` 和 `baz` 这三个节点在完成各自执行后通过写入对应的通道驱动后续节点的执行，所以节点`qux`在`bar`和`baz`在执行后都会收到信号，但是它可以读取`output`这个Channel的内容确定两个前置节点是否成功执行。

## 7. 更好的解决方案

上面的例子采用**多次触发**并且让节点自行判断前置条件是否满足的方式解决了多节点依赖问题，虽然实现起来也很简单，对性能也没有太大的影响，但我们有更好的选择。在众多预定义的通道类型中，有一个名为`NamedBarrierValue`的通道就是为这种应用场景服务的。该通道预定义一组名称集合，其自身会维护一个集合来存储写入的值，只有两个集合一致性的时候，它才会视为有更新并触发订阅它的节点。为了解决`qux` 针对 `bar` 和 `baz` 的依赖，我们只需要按照如下的方式将 `qux` 这个通道定义成`NamedBarrierValue`类型，并将作为名称集合的`names`设置为`{"bar","baz"}`。 `bar` 和 `baz` 在完成执行后只需要将各自的名称写入此通道即可。

```python
from langgraph.channels import LastValue, BinaryOperatorAggregate,NamedBarrierValue
from langgraph.pregel import Pregel, NodeBuilder
import operator

foo = (NodeBuilder()
    .subscribe_to("foo",read=False)
    .write_to(output=["foo"], baz=None))
bar = (NodeBuilder()
    .subscribe_to("bar",read=False)
    .write_to(output=["bar"], qux="bar"))
baz = (NodeBuilder()
    .subscribe_to("baz",read=False)
    .write_to(output=["baz"], qux="baz"))
qux = (NodeBuilder()
    .subscribe_to("qux",read=False)
    .write_to(output=["qux"]))

app = Pregel(
    nodes={
        "foo":foo,
        "bar":bar,
        "baz":baz,
        "qux":qux
    },
    channels={
        "foo": LastValue(None),
        "bar": LastValue(None),
        "baz": LastValue(None),
        "qux": **NamedBarrierValue(str, names={"bar","baz"}),**
        "output": BinaryOperatorAggregate(list, operator=operator.add)
    },
    input_channels=["foo","bar"],
    output_channels=["output"]
)

result = app.invoke({"foo": None, "bar": None})
sequences:list[list[str]] = [
    ["foo","baz","bar","qux"],
    ["bar","foo","baz","qux"],
    ["foo","baz","bar","qux"]]
assert result["output"] in sequences
```
