# [FastMCP设计、原理与应用-04]Primitive——MCP最核心的概念

工具、资源和提示词在[MCP规范](https://modelcontextprotocol.io/)被同一命名为原语（Primitive）。在计算机科学中，Primitive指的是不可分割、最基础的构建块。MCP官方文档将这三者定义为原语，是为了明确它们是构成AI与外部数据/环境交互的最基础元素：

- 资源：代表“数据”层（如文件、数据库内容），是LLM获取外部信息的读取入口；
- 工具：代表“行动”层（如发送邮件、执行代码），是LLM改变外部状态的可执行函数；
- 提示词：代表“逻辑/指令”层（如预设的调试模板），是引导LLM行为的标准化指令；

在[MCP规范](https://modelcontextprotocol.io/)中，除了最常被提及的三大核心原语外，协议规范中还包含其他原语，比如表示后台任务也是一个核心的原语。[mcp库](https://github.com/modelcontextprotocol)定义了专门的类型（它们一般定义在`mcp.types`模块下）来表示这些原语。在FastMCP中，这些原语对应着相应的组件，所以要彻底理解FastMCP的设计，得先认识[MCP规范](https://modelcontextprotocol.io/)的三大核心原语。

## 1. 基础类型

[mcp库](https://github.com/modelcontextprotocol)为原语定义了统一的基类`BaseMetadata`。从如下的定义可知，原语类型被定义成Pydantic模型，`name`和`title`是它们公共的数据成员。

```python
class BaseMetadata(BaseModel):
    name: str
    title: str | None = None
```

### 1.1 请求

对于任何一个MCP操作，表示由发送方（可以是客户端也可以是服务端）发起的请求类型都是如下这个`Request`的子类，这是一个泛型的Pydantic模型。由于MCP采用JSON-RPC协议，所以请求必需指定一个明确的方法（对应method字段），作为参数的`params`可以是`None`（没有输入）或者是一个字典，还可以是一个`RequestParams`对象。

```python
class Request(BaseModel, Generic[RequestParamsT, MethodT]):
    method: MethodT
    params: RequestParamsT
    model_config = ConfigDict(extra="allow")

RequestParamsT = TypeVar("RequestParamsT", bound=RequestParams | dict[str, Any] | None)
MethodT = TypeVar("MethodT", bound=str)
```

`RequestParams`内部类`Meta`中的`progressToken`体现了“进度追踪”的功能。它允许客户端在发送请求时，挂载一个由ProgressToken（字符串或者整数）作为“追踪 ID”。如果服务器支持，它会在处理请求的过程中，以通知的形式（JSON-RPC方法为`notifications/progress`）推送进度更新。

```python
ProgressToken = str | int
class RequestParams(BaseModel):
    class Meta(BaseModel):
        progressToken: ProgressToken | None = None
        model_config = ConfigDict(extra="allow")

    task: TaskMetadata | None = None
    meta: Meta | None = Field(alias="_meta", default=None)
class TaskMetadata(BaseModel):
    model_config = ConfigDict(extra="allow")
    ttl: Annotated[int, Field(strict=True)] | None = None
```

大部分的原语最终都通过一个函数来定义。函数执行可长可短，如果客户端请求的原语涉及长耗时操作，长时间等待会带来很差的用户体验。为了解决这个问题，前台执行的操作会转换成后台执行的任务，此时客户端会得到任务的ID并利用它来跟踪任务的状态，并最终提取指定结果，这被称为**后台任务协议**。由于我们不能保证客户端会在未来哪个时间点读取任务的执行结果，服务端只能只能将其缓存起来。执行结果又不能被永久存储，所以需要`TaskMetadata`的`ttl`字段设置一个时间限制。一旦超出这一时限，任务的指定结果就会被清除。

所有的`List`操作都以分页的形式返回结果，这样的请求通过如下所示的`PaginatedRequest`类型表示。这样的请求具有一个`PaginatedRequestParams`类型的参数，它`cursor`字段表示的游标起到**页码**的作用。第一次请求，会返回表示下一页的`cursor`（被命名为`nextCursor`），下次请求会携带上次返回的`cursor`，服务端就会返回下一页的内容。

```python
class PaginatedRequest(Request[PaginatedRequestParams | None, MethodT], Generic[MethodT]):
    params: PaginatedRequestParams | None = None

class PaginatedRequestParams(RequestParams):
    cursor: Cursor | None = None
```

### 1.2 结果

请求的结果都继承自如下这个`Result`基类，它利用`meta`字段表示的字典存储元数据信息。MCP引入`meta`是为了处理 **带外数据（Out-of-band Data）**以解耦业务与协议控制。如果使用`result`字段承载业务信息，而像 `progressToken`、`ttl`或特定的调试信息塞进`result`就不合适。

```python
class Result(BaseModel):
    meta: dict[str, Any] | None = Field(alias="_meta", default=None)
    model_config = ConfigDict(extra="allow")
```

分页的结果通过如下这个`PaginatedResult`类型来表示，它的`nextCursor`字段返回的游标表示下一页的页码。如果返回None，表示已经**翻到最后一页**了。

```python
class PaginatedResult(Result):
    nextCursor: Cursor | None = None
```

### 1.3 多媒体内容

请求和回复消息可能携带一段或者多段多媒体内容，基于文本、图片、音频内容通过如下三个类型表示。`TextContent`和`ImageContent`可以同时通过`type`和`mimeType`字段进行区分媒体类型，`AudioContent`则只有`mimeType`字段。`TextContent`利用`text`字段表示文本内容，`ImageContent`和`AudioContent`则利用`data`字段承载图片和音频内容。

```python
class TextContent(BaseModel):
    type: Literal["text"]
    text: str
    annotations: Annotations | None = None
    meta: dict[str, Any] | None = Field(alias="_meta", default=None)    
    model_config = ConfigDict(extra="allow")

class ImageContent(BaseModel):
    type: Literal["image"]
    data: str
    mimeType: str
    annotations: Annotations | None = None
    meta: dict[str, Any] | None = Field(alias="_meta", default=None)
    model_config = ConfigDict(extra="allow")

class AudioContent(BaseModel):
    data: str
    mimeType: str
    annotations: Annotations | None = None
    meta: dict[str, Any] | None = Field(alias="_meta", default=None)
    model_config = ConfigDict(extra="allow")

class Annotations(BaseModel):
    audience: list[Role] | None = None
    priority: Annotated[float, Field(ge=0.0, le=1.0)] | None = None
    model_config = ConfigDict(extra="allow")

Role = Literal["user", "assistant"]
```

它们公共字段`annotations`返回一个`Annotations`对象，它具有如下两个字段：

- audience：内容的受众（`user`或者`assistant`），最终会转换成Chat模型消息绑定的角色；
- priority：优先级或者重要程度，是一个`[0,1]`区间范围内容数组，值越大，优先级越高；

## 2. 资源

资源这一原语又分为通过固定URI标识的**静态资源**和利用URI模板定位的**动态资源**。前者通过如下这个`Resource`类型表示，提供了资源的地址、描述、MIME类型、数据大小、图标、受众、优先级和元数据。

```python
class Resource(BaseMetadata):
    uri: Annotated[AnyUrl, UrlConstraints(host_required=False)]
    description: str | None = None
    mimeType: str | None = None
    size: int | None = None
    icons: list[Icon] | None = None
    annotations: Annotations | None = None
    meta: dict[str, Any] | None = Field(alias="_meta", default=None)
    model_config = ConfigDict(extra="allow")
```

利用URI模板定位的动态资源通过如下这个`ResourceTemplate`类型表示。它不仅仅是将`Resource`的`uri`替换换成`uriTemplate`，本质上它代表的是**一组资源**，所以它没有`size`字段。

```python
class ResourceTemplate(BaseMetadata):
    uriTemplate: str
    description: str | None = None
    mimeType: str | None = None
    icons: list[Icon] | None = None
    annotations: Annotations | None = None
    meta: dict[str, Any] | None = Field(alias="_meta", default=None)
    model_config = ConfigDict(extra="allow")
```

### 2.1 读取资源列表

读取静态资源列表的请求通过`ListResourcesRequest`类型表示，它通过继承`ListResourcesRequest`提供分页获取资源的能力，`method`字段返回固定的JSON-RPC的方法`resources/list`。结果类型为`ListResourcesResult`，它派生于`PaginatedResult`，获取的资源列表为一组（页）`Resource`对象。

```python
class ListResourcesRequest(PaginatedRequest[Literal["resources/list"]]):
    method: Literal["resources/list"] = "resources/list"

class ListResourcesResult(PaginatedResult):
    resources: list[Resource]
```

读取动态资源列表的请求和结果的类型分别为`ListResourceTemplatesRequest`和`ListResourceTemplatesResult`，前者具有不同的是JSON-RPC的方法（`resources/templates/list`），后则是对一组`ResourceTemplate`对象的封装。

```python
class ListResourceTemplatesRequest(PaginatedRequest[Literal["resources/templates/list"]]):
    method: Literal["resources/templates/list"] = "resources/templates/list"
class ListResourceTemplatesResult(PaginatedResult):
    resourceTemplates: list[ResourceTemplate]
```

### 2.2 读取资源的内容

读取指定资源内容的请求类型为`ReadResourceRequest`，对于JSON-RPC方法为`resources/read`，作为请求参数的`ReadResourceRequestParams`对象只需要指定标识资源的URI。

```python
class ReadResourceRequest(Request[ReadResourceRequestParams, Literal["resources/read"]]):
    method: Literal["resources/read"] = "resources/read"
    params: ReadResourceRequestParams
class ReadResourceRequestParams(RequestParams):
    uri: Annotated[AnyUrl, UrlConstraints(host_required=False)]
    model_config = ConfigDict(extra="allow")
```

返回的`ReadResourceResult`对象承载了资源的内容，可以是一组表示文本资源内容的`TextResourceContents`对象，也可以是表示二进制资源内容的`BlobResourceContents`对象（`blob`字段返回的字符串为资源内容的base64编码）。这两个类型具有相同的基类`ResourceContents`，它提供了资源内容的URI、MIME类型和元数据。

```python
class ReadResourceResult(Result):
    contents: list[TextResourceContents | BlobResourceContents]

class TextResourceContents(ResourceContents):
    text: str

class ResourceContents(BaseModel):
    uri: Annotated[AnyUrl, UrlConstraints(host_required=False)]
    mimeType: str | None = None
    meta: dict[str, Any] | None = Field(alias="_meta", default=None)
    model_config = ConfigDict(extra="allow")
    
class BlobResourceContents(ResourceContents):
    blob: str
```

### 2.3 FastMCP客户端实现

FastMCP针对[MCP规范](https://modelcontextprotocol.io/)资源原语的实现清晰地体现在客户端API的定义上。如下面的代码片段所示，`Client`继承了`ClientResourcesMixin`这个混入类，上面介绍的资源相关的所有操作都定义在这个类型中。List操作都提供了两种实现，以`_mcp`后缀命名的方法是对MCP协议的实现（利用游标分页），另一个方会返回所有可用的资源，但是会限制最大返回的数量（默认为250）。如果读取资源以后台任务的方式执行，返回的将是代表资源读取任务的`ResourceTask`对象。

```python
class Client(
    Generic[ClientTransportT],
    ClientResourcesMixin,
    ClientPromptsMixin,
    ClientToolsMixin,
    ClientTaskManagementMixin,
)

AUTO_PAGINATION_MAX_PAGES = 250
class ClientResourcesMixin:
    async def list_resources_mcp(
        self: Client, *, cursor: str | None = None
    ) -> mcp.types.ListResourcesResult

    async def list_resources(
        self: Client,
        max_pages: int = AUTO_PAGINATION_MAX_PAGES,
    ) -> list[mcp.types.Resource]

    async def list_resource_templates_mcp(
        self: Client, *, cursor: str | None = None
    ) -> mcp.types.ListResourceTemplatesResult:

    async def list_resource_templates(
        self: Client,
        max_pages: int = AUTO_PAGINATION_MAX_PAGES,
    ) -> list[mcp.types.ResourceTemplate]:

    async def read_resource_mcp(
        self: Client, uri: AnyUrl | str, meta: dict[str, Any] | None = None
    ) -> mcp.types.ReadResourceResult:

    @overload
    async def read_resource(
        self: Client,
        uri: AnyUrl | str,
        *,
        version: str | None = None,
        meta: dict[str, Any] | None = None,
        task: Literal[False] = False,
    ) -> list[mcp.types.TextResourceContents | mcp.types.BlobResourceContents]: ...

    @overload
    async def read_resource(
        self: Client,
        uri: AnyUrl | str,
        *,
        version: str | None = None,
        meta: dict[str, Any] | None = None,
        task: Literal[True],
        task_id: str | None = None,
        ttl: int = 60000,
    ) -> ResourceTask: ...

    async def read_resource(
        self: Client,
        uri: AnyUrl | str,
        *,
        version: str | None = None,
        meta: dict[str, Any] | None = None,
        task: bool = False,
        task_id: str | None = None,
        ttl: int = 60000,
    ) -> (
        list[mcp.types.TextResourceContents | mcp.types.BlobResourceContents]
        | ResourceTask
    )
```

## 3. 工具

工具这一个原语通过如下这个`Tool`类型来表示，它不仅描述了工具“长什么样”，还定义了它“如何运行”。

```python
class Tool(BaseMetadata):
    description: str | None = None
    inputSchema: dict[str, Any]
    outputSchema: dict[str, Any] | None = None
    icons: list[Icon] | None = None
    annotations: ToolAnnotations | None = None
    meta: dict[str, Any] | None = Field(alias="_meta", default=None)
    execution: ToolExecution | None = None
    model_config = ConfigDict(extra="allow")
```

如下为字段说明：

- description：工具的说明书。这是给LLM看的，模型靠这段文字判断什么时候该调用这个工具;
- inputSchema：工具输入数据结构，LLM会根据这个结构来生成调用参数；
- outputSchema：工具输出数据结构，这有助于LLM理解工具输出的数据含义;
- icons：工具的图标列表。主要用于在客户端的界面上美化显示;
- annotations：包含一些语义标签，帮助客户端更好地理解工具的意图;
- meta: 协议内部使用的元数据，通常包含版本信息或非标准的扩展数据;
- execution: 主要用于说明能否或者是否强制以后台任务的形式执行；

`Tool`的`annotations`字段返回的`ToolAnnotations`对象定义了工具的 **元语义属性**。如果说`inputSchema`是告诉模型工具的语法（怎么传参），那么`ToolAnnotations`就是在告诉模型和客户端工具具有的风格与风险特征（调用时要注意什么）。它提供一些提示（Hint）对于构建安全、可靠且具备自主决策能力的Agent至关重要。

```python
class ToolAnnotations(BaseModel):
    title: str | None = None
    readOnlyHint: bool | None = None
    destructiveHint: bool | None = None
    idempotentHint: bool | None = None
    openWorldHint: bool | None = None
    model_config = ConfigDict(extra="allow")
```

如下为字段说明：

- readOnlyHint: 只读提示。明确该工具仅读取数据，不会改变任何系统状态。AI可以放心地频繁调用它来获取上下文，而无需担心产生副作用；
- destructiveHint: 破坏性提示。提示工具是否会会执行不可逆的操作（如删除文件、清空数据库、关闭服务）。客户端看到这个标签后，通常会强制弹出人工确认对话框，防止AI误操作导致数据丢失。
- idempotentHint： 幂等性提示。提示多次调用该工具（使用相同参数）是否会产生相同的结果且不会有额外副作用。
- openWorldHint：开放世界提示。提示工具的执行结果是否受到外部不可控因素影响（即“非封闭系统”）。告诉模型，即便参数没变，由于外部环境（如网络 API、传感器数据）在变，结果可能随时间变化。这会引导模型在需要最新数据时重新调用，而不是依赖缓存；

`execution`字段返回一个`ToolExecution`对象，它的`taskSupport`字段于前面介绍的**后台任务协议**有关，表示工具以怎样的方式对这种功能提供支持。

```python
class ToolExecution(BaseModel):
    model_config = ConfigDict(extra="allow")
    taskSupport: TaskExecutionMode | None = None
    Default: "forbidden"
TaskExecutionMode = Literal["forbidden", "optional", "required"]
```

`taskSupport`字段返回的`TaskExecutionMode`具有如下三个选项，默认为`forbidden`：

- forbidden：严禁采用后台任务执行工具；
- optional：可以采用后台任务执行工具，可能短时间内完成的工具采用常规执行方式（立即执行，并返回结果），若在指定的时间内容没有执行完，变转入后台执行；
- required: 强制转入后台执行。

### 3.1 读取工具列表

工具涉及两个操作分别是**读取工具列表**和**调用工具**，前者的输入和输出类型分别`ListToolsRequest`和`ListToolsResult`。`ListToolsRequest`继承自表示分页请求的`PaginatedRequest`类型，它反映了读取工具列表采用的JSON-RPC方法`tools/list`。

```python
class ListToolsRequest(PaginatedRequest[Literal["tools/list"]]):
    method: Literal["tools/list"] = "tools/list"

class ListToolsResult(PaginatedResult):
    tools: list[Tool]    
```

`ListToolsResult`继承自`PaginatedResult`对象，其`tools`返回当页的工具列表，表示工具的正是上面介绍的`Tool`对象。

### 3.2 调用工具

如下所示的`CallToolRequest`类型表示工具调用请求，表示JSON-RPC方法的`method`固定为`tools/call`，`name`和`arguments`字段用于指定工具名称和参数（无参工具函数可以缺省）。

```python
class CallToolRequest(Request[CallToolRequestParams, Literal["tools/call"]]):
    method: Literal["tools/call"] = "tools/call"
    params: CallToolRequestParams

class CallToolRequestParams(RequestParams):
    name: str
    arguments: dict[str, Any] | None = None
    model_config = ConfigDict(extra="allow")
```

工具执行后的结果被封装成一个`CallToolResult`对象。表示具体内容的`conent`字段是一个`ContentBlock`对象的列表，可以是`TextContent`、`ImageContent`和`AudioContent`对象表示的多媒体内容，也可以是通过`ResourceLink`或者`EmbeddedResource`表示的资源。

```python
class CallToolResult(Result):
    content: list[ContentBlock]
    structuredContent: dict[str, Any] | None = None
    isError: bool = False
ContentBlock = TextContent | ImageContent | AudioContent | ResourceLink | EmbeddedResource
```

`ResourceLink`表示的资源通常是动态生成或临时产生的，所以不会出现在`resources/list`请求返回的集合中。`ResourceLink`只包含定位资源的URI，而`EmbeddedResource`表示携带内容的资源，具体内容体现在它的`resource`字段返回的`TextResourceContents`或者`BlobResourceContents`对象上。两个类型定义如下：

```python
class ResourceLink(Resource):
    type: Literal["resource_link"]

class EmbeddedResource(BaseModel):
    type: Literal["resource"]
    resource: TextResourceContents | BlobResourceContents
    annotations: Annotations | None = None
    meta: dict[str, Any] | None = Field(alias="_meta", default=None)
    model_config = ConfigDict(extra="allow")
```

### 3.3 FastMCP客户端的实现

FastMCP针对[MCP规范](https://modelcontextprotocol.io/)工具原语的实现清晰地体现在客户端API的定义上。如下面的代码片段所示，`Client`继承了`ClientToolsMixin`这个混入类，上面介绍的工具相关的所有操作都定义在这个类型中。`List`操作都提供了两种实现，以`_mcp`后缀命名的方法是对MCP协议的实现（利用游标分页），另一个方会返回所有可用的工具，但是会限制最大返回的数量（默认为250）。如果工具调用以后台任务的方式执行，返回的将是代表工具执行任务的`ToolTask`对象。

```python
class Client(
    Generic[ClientTransportT],
    ClientResourcesMixin,
    ClientPromptsMixin,
    ClientToolsMixin,
    ClientTaskManagementMixin,
):

class ClientToolsMixin:
    async def list_tools_mcp(
        self: Client, *, cursor: str | None = None
    ) -> mcp.types.ListToolsResult

    async def list_tools(
        self: Client,
        max_pages: int = AUTO_PAGINATION_MAX_PAGES,
    ) -> list[mcp.types.Tool]

    async def call_tool_mcp(
        self: Client,
        name: str,
        arguments: dict[str, Any],
        progress_handler: ProgressHandler | None = None,
        timeout: datetime.timedelta | float | int | None = None,
        meta: dict[str, Any] | None = None,
    ) -> mcp.types.CallToolResult

    @overload
    async def call_tool(
        self: Client,
        name: str,
        arguments: dict[str, Any] | None = None,
        *,
        version: str | None = None,
        timeout: datetime.timedelta | float | int | None = None,
        progress_handler: ProgressHandler | None = None,
        raise_on_error: bool = True,
        meta: dict[str, Any] | None = None,
        task: Literal[False] = False,
    ) -> CallToolResult: ...

    @overload
    async def call_tool(
        self: Client,
        name: str,
        arguments: dict[str, Any] | None = None,
        *,
        version: str | None = None,
        timeout: datetime.timedelta | float | int | None = None,
        progress_handler: ProgressHandler | None = None,
        raise_on_error: bool = True,
        meta: dict[str, Any] | None = None,
        task: Literal[True],
        task_id: str | None = None,
        ttl: int = 60000,
    ) -> ToolTask: ...

    async def call_tool(
        self: Client,
        name: str,
        arguments: dict[str, Any] | None = None,
        *,
        version: str | None = None,
        timeout: datetime.timedelta | float | int | None = None,
        progress_handler: ProgressHandler | None = None,
        raise_on_error: bool = True,
        meta: dict[str, Any] | None = None,
        task: bool = False,
        task_id: str | None = None,
        ttl: int = 60000,
    ) -> CallToolResult | ToolTask
```

## 4. 提示词

提示词（模板）的原语通过如下这个`Prompt`类型表示，它提供过了提示词（模板）的描述、参数（模板占位符）列表、图标和元数据。

```python
class Prompt(BaseMetadata):
    description: str | None = None
    arguments: list[PromptArgument] | None = None
    icons: list[Icon] | None = None
    meta: dict[str, Any] | None = Field(alias="_meta", default=None)
    model_config = ConfigDict(extra="allow")
```

提示词模板参数通过如下这个`PromptArgument`类型表示，它提供表示参数名称和描述的`name`和`description`字段，`required`字段用以指示当前参数是否可以缺省。

```python
class PromptArgument(BaseModel):
    name: str
    description: str | None = None
    required: bool | None = None
    model_config = ConfigDict(extra="allow")
```

### 4.1 读取提示词列表

读取提示词列表的请求通过`ListPromptsRequest`类型表示，它依然是`PaginatedRequest`的子类，表示JSON-RPC方法的`method`字段固定为`prompts/list`。返回的结果类型`ListPromptsResult`派生于`PaginatedResult`，是对一组`Prompt`对象的封装。

```python
class ListPromptsRequest(PaginatedRequest[Literal["prompts/list"]]):
    method: Literal["prompts/list"] = "prompts/list"

class ListPromptsResult(PaginatedResult):
    prompts: list[Prompt]
```

### 4.2 读取指定提示词

利用指定的参数填充指定提示词模板，进而得到完整提示词的操作请求通过如下所示的`GetPromptRequest`类型表示，表示JSON-RPC方法的`method`字段固定为`prompts/get`,作为参数的`GetPromptRequestParams`对象用来指定提示词名称和填充参数（可选，是否指定取决于是否定义了占位符）。

```python
class GetPromptRequest(Request[GetPromptRequestParams, Literal["prompts/get"]]):
    method: Literal["prompts/get"] = "prompts/get"
    params: GetPromptRequestParams

class GetPromptRequestParams(RequestParams):
    name: str
    arguments: dict[str, str] | None = None
    model_config = ConfigDict(extra="allow")
```

作为结果的完整提示词被封装在返回的`GetPromptResult`对象中，除了表示描述信息的`description`字段外，`GetPromptResult`还利用`messages`返回一组`PromptMessage`对象。每个`PromptMessage`对象利用`role`和`content`表示提示词的受众和通过`ContentBlock`对象表示的内容。对于常规的文本字符串，`PromptMessage`的`content`会返回一个`TextContent`对象。很明显，`PromptMessage`是为了适配Chat模型的消息。

```python
class GetPromptResult(Result):
    description: str | None = None
    messages: list[PromptMessage]

class PromptMessage(BaseModel):
    role: Role
    content: ContentBlock
    model_config = ConfigDict(extra="allow")
```

### 4.3 FastMCP客户端的实现

FastMCP针对[MCP规范](https://modelcontextprotocol.io/)提示词原语的实现清晰地体现在客户端API的定义上。如下面的代码片段所示，`Client`继承了`ClientPromptsMixin`个混入类，上面介绍的提示词相关的所有操作都定义在这个类型中。`List`操作都提供了两种实现，以·后缀命名的方法是对MCP协议的实现（利用游标分页），另一个方会返回所有可用的提示词，但是会限制最大返回的数量（默认为250）。如果工具调用以后台任务的方式执行，返回的将是代表提示词读取任务的`PromptTask`对象。

```python
class Client(

    ClientToolsMixin,
    ClientTaskManagementMixin,
)

class ClientPromptsMixin:

    async def list_prompts(
        self: Client,
        max_pages: int = AUTO_PAGINATION_MAX_PAGES,
    ) -> list[mcp.types.Prompt]

    async def get_prompt_mcp(
        self: Client,
        name: str,
        arguments: dict[str, Any] | None = None,
        meta: dict[str, Any] | None = None,
    ) -> mcp.types.GetPromptResult

    @overload

        self: Client,
        name: str,
        arguments: dict[str, Any] | None = None,
        *,
        version: str | None = None,
        meta: dict[str, Any] | None = None,
        task: Literal[False] = False,
    ) -> mcp.types.GetPromptResult: ...
    @overload
    async def get_prompt(
        self: Client,
        name: str,
        arguments: dict[str, Any] | None = None,
        *,
        version: str | None = None,
        meta: dict[str, Any] | None = None,
        task: Literal[True],
        task_id: str | None = None,
        ttl: int = 60000,
    ) -> PromptTask: ...
    async def get_prompt(
        self: Client,
        name: str,
        arguments: dict[str, Any] | None = None,
        *,
        version: str | None = None,
```
